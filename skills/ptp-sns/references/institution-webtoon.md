# 기관소개·역할 설명 웹툰에서 SNS까지

출연진은 [캐릭터 세트 선택](character-sets.md)을 우선한다. 이 문서의 테오·피오는 기본 세트 예시이며 다른 세트를 선택하면 해당 멤버의 역할·기준 이미지로 바꾼다. 캐릭터 없음은 사물·도식·내레이션의 사건 흐름으로 설명한다. 기존 테오·피오 연재는 지정 출연진을 유지한다.

공고가 없어도 포항TP의 설립 배경·목적·주요 기능·시설·정책을 테오·피오의 이야기로 설명한다. 명시된 웹툰 형식을 다시 묻거나 10초 기본값으로 단일 홍보 이미지로 바꾸지 않는다. 웹툰이라고 모든 요청을 정해진 장수나 동일한 말풍선 틀에 넣지 않는다.

## 사실과 범위

- `content_category=institution-explainer`, `workflow=creative`, `content_mode=educational-comic|social-toon`으로 기록한다. 테크노파크 일반 역할과 포항TP의 설립일·특성을 구분한다. 공식 재단개요·연혁·부서 안내 및 한국테크노파크진흥회 자료를 실행 시 확인하고, 사실·출처 URL·확인일을 컷에 연결한다.
- 기본 출처는 [포항TP 재단개요](https://www.ptp.or.kr/main/html.do?menu_idx=106), [테크노파크란](https://www.technopark.or.kr/www/contents/33.do?mid=1082), [기능 및 역할](https://www.technopark.or.kr/www/contents/8.do?mid=1003)다. 설립일·조직·산업분야를 기억만으로 고정하지 않는다.
- 상시 기관소개에는 모집 접수기간이 없으므로 `application_period_check=not-applicable`과 이유를 기록한다. 실제 모집·행사·지원사업 신청을 홍보하면 해당 부분은 공고 ID와 원래 기간 검사를 반드시 적용한다. 기관소개 키로 마감 공고 검사를 우회하지 않는다. 없는 마감·금액·혜택·성과를 만들어 넣지 않는다.

## 이야기가 설명하게 만들기

독자의 실제 질문과 답을 먼저 정하고 테오·피오의 행동으로 원인→연결→변화를 보여준다. 예: 좋은 기술이 제품까지 가려면 무엇이 필요한가 → 기업·대학·연구소·지자체의 협력 → 정책·창업·연구·장비·인재·판로 지원 → 지역산업 혁신. 항목 나열형 안내판에 캐릭터만 추가하지 않는다.

기관을 설명하는 비유는 사용할 수 있으나 실제 시설·담당 업무·성공사례처럼 표현하지 않는다. 지원기관의 연결·육성 역할과 실제 심사·선정·성과 보장을 구분한다. 새 편은 최근 완성본의 구성·카메라·서사와 비교해 다른 전달 방식을 선택한다.

장수·컷 수는 실제 설명량과 모바일 독해로 정한다. 제작·검수·게시가 위임됐으면 내부 비교와 선택 이유를 남기고 진행하며 별도의 창작 승인 단계를 추가하지 않는다. 그림과 대사 통합 생성을 기본으로 하고 승인 앵커로 캐릭터를 잠근다. [웹툰 계약](webtoon-content-mode.md)의 연속성·화자·안전영역 검사를 적용한다.

## 지원사업 길찾기 연재의 설명 설계

2026년 연재의 9~34화 신규 제작은 **게시 이미지 5~7장**으로 구성한다. 말풍선 수나 한 이미지 속 컷 수와 별개로 센다. 5장 기본 구성은 **생활 속 질문 → 쉬운 뜻 → 구체적인 사례 → 헷갈리는 점 또는 결과 → 독자가 할 일**이다. 사례의 중간 과정이나 비슷한 두 개념을 따로 설명해야 하면 6장, 여러 개념 또는 절차를 한 장씩 풀어야 하면 7장으로 나눈다. 필요한 설명의 수로 장수를 고르고 표지나 QR만으로 분량을 채우지 않는다.

- 한 회차에 한 가지 질문을 고르고, 한 장마다 그 질문에 필요한 답을 하나씩 더한다. 같은 인물과 물건을 따라가며 무엇을 했고 무엇을 알게 됐는지 그림과 대사로 연결한다. 앞 장의 대답을 반복하기보다 다음 판단에 필요한 정보를 더한다.
- 어려운 이름이 꼭 필요하면 일상어로 먼저 설명하고 공식 이름을 붙인다. 정의와 생활 속 비유, 실제 조건이 달라지는 지점을 구분한다. 고학년 초등학생이 처음 읽는다고 가정하고, 모르는 전문 용어로 다른 용어를 설명하지 않는다. 예외와 기관별 서류는 결론에 필요한 것만 다룬다.
- 정보는 캡션에만 두지 않는다. 이미지에서 **무엇인지, 예시에서는 어떻게 되는지, 무엇을 혼동하면 안 되는지, 다음에 무엇을 확인할지** 이어져야 한다. 마지막 장의 행동은 한 가지로 좁히고 QR 옆에 찾아가는 이름을 적는다.
- 이미지 생성 전에 장수 선택 이유와 장별 한 문장 설명을 쓴다. 가운데 장에 쉬운 뜻을 알려 주는 `explain`과 실제 행동으로 보여 주는 `example`을 각각 하나 이상 둔다. 회차별 제작 브리프가 편성표에 있으면 먼저 읽고 그 회차의 공식 출처와 콘티를 적용한다. 실제 PNG의 360px 미리보기를 순서대로 읽고, 캡션 없이 개념 설명 질문 하나와 새로운 상황에 적용하는 질문 하나에 대답할 수 있는지 모델이 검토한다. 각각 어느 장에서 답을 찾는지 기록한다. 읽기 검수가 끝나지 않았으면 게시하지 않는다.

예를 들어 시험과 인증을 다룰 때는 장난감 수레 하나로 **도구 사용 → 조건을 정해 관찰 → 성적서에서 결과 읽기 → 별도의 인증 기준 확인**을 보여준다. 성적서 한 장으로 아직 시험하지 않은 조건까지 알 수 있는지 묻고, 필요한 시험 항목과 받을 결과물을 적게 한다.

## 패키지와 재개

- 작품·주제·회차별 안정된 키 `ptp:institution:<topic>:ep01`을 사용한다. 같은 이야기를 재실행한다고 날짜·캡션마다 새 키를 만들지 않는다. 채널별 게시 키는 기존 공통 장부의 `source_key + platform + account`다.
- `content_history.py start/finish/check`는 기관소개 키도 지원한다. 공통 제작 장부에 완성된 PNG 순서·문안·대체텍스트·콘티·출처·검수의 해시 manifest를 남긴다. `publication_history.py`의 일반 콘텐츠 경로로 채널별 `submitting`을 기록하고 실제 결과를 같은 시도로 마무리한다. 기관소개는 공고 기간 게이트 대상이 아니지만 파일 무결성·실제 검수·게시 권한·중복 검사는 유지한다.
- 기존 공개·예약·초안을 작품명과 주제로 검색하고 조회 범위를 기록한다. 확인 범위의 부재와 전체 과거 부재를 구분한다. 중단·결과 불명은 원래 원격 시도를 먼저 확인한다.
- 최종 장에는 공식 기관소개 또는 관련 서비스 QR과 같은 기기에서 따라갈 문자 경로를 둔다. 지원사업 확인은 각 공고 조건을 따름을 캡션에 안내한다. 생성 QR은 최종 파일에서 실제 URL로 해독된 경우에만 사용한다.
- 단축주소 기본값은 기관소개에도 적용한다. `config/link-policy.json`을 읽고 원래 공식 URL과 검증된 단축주소를 분리 기록한다. `shorten_notice_url.py --purpose institution`으로 단축주소를 먼저 확정한 뒤 그 주소로 QR과 이미지의 문자 주소를 생성한다. 최종 해독이 긴 원문 URL을 읽었다면 단축주소 적용 통과로 처리하지 않는다.
- 생성 QR이 인식되지 않으면 같은 전체 장면을 반복 재생성하지 않는다. 한 번의 국소 보정 뒤에도 실패하면 원본과 상태를 보존한다. 사용자가 정확한 코드 삽입을 명시 허용한 경우 QR 영역만 원본 코드로 교체하고 영역 밖 픽셀 동일성·원본 및 축소본 해독을 확인한다. 통합 생성 원본이 바이트 그대로라고 주장하지 말고 QR 보정 범위와 사용자 지정 근거를 기록한다. 다른 편집 방식의 허용이 없으면 그 지점만 확인한다.
- 채널별 맞춤 문안·대체텍스트·게시 순서를 확인하고 저장된 내장 브라우저 세션을 재사용한다. 제작과 게시 위임이 명확하면 두 지정 재단 계정에 게재하고 공개 주소·장수·이미지·문안·QR을 검증한다. 실독자/사람 검토가 없으면 모델 검수로만 기록한다.
