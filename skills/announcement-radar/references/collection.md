# 수집 절차 (collection.md)

소스 목록 자체는 작업 폴더 `sources.json`에 있고(`scripts/sources.py list`로 확인), 이 파일은 **어떻게 조회하는지**를 정한다.

## 목차
- §1. 소스 구조와 필드
- §2. 4단계 조회 (fallback)
- §3. 조회 예산과 순서
- §4. 사전조사(수요조사·RFP 공개) 찾기
- §5. 자동 추가 규칙
- §6. 중복·마감·실패 처리

## §1. 소스 구조와 필드

| Tier | 범위 | 기본 개수 |
| --- | --- | --- |
| 1 | 통합 포털 — IRIS, NTIS, 기업마당, e나라도움, 나라장터, K-Startup | 6 |
| 2 | 부처별 전담기관 — KEIT, KIAT, KETEP, TIPA, NIPA, KHIDI, KIMST 등 | 28 |
| 3 | 지역 — 경상북도, 포항시, 경북TP, 포항TP(모니터링 전용) | 4 |

`sources.json`의 주요 필드:

| 필드 | 뜻 |
| --- | --- |
| `priority` | 필수(Tier 1) / 상(매 스캔) / 중(예산이 남으면) / 하(7일마다 또는 단일 요청 시) |
| `method` | 조회 순서. `api>websearch`, `webfetch>websearch`, `websearch>webfetch`, `iris`(자체 조회 대신 IRIS 결과로 대체) |
| `iris` | ● R&D 공고를 IRIS가 모두 커버 / ◐ 일부 / ○ 안 함 / ? 미확인 / - 해당 없음 |
| `verified` | F 직접 열어 게시물 확인 / F* 열리나 목록이 JS로 그려짐 → WebSearch 우선 / S 검색으로만 확인 / 미확인 / API |
| `presurvey` | 수요조사·RFP 공개를 올리는 소스 (§4에서 우선 조회) |
| `monitor_only` | 자체 발주 확인용. 채점·브리핑 대상 아님 |
| `fail_count` | 연속 실패 횟수. 3 이상이면 "점검 필요" |

2025.10 정부조직 개편 기준 부처명을 쓴다: 산업통상부(구 산업통상자원부), 기후에너지환경부(에너지 기능 이관), 기획예산처, 지식재산처(구 특허청).
KAIT(한국정보통신진흥협회)는 산업기술 전담기관이 아니다. 산업기술 쪽은 KIAT(한국산업기술진흥원)다.

## §2. 4단계 조회 (fallback)

```
① 공공데이터포털 API — e나라도움·나라장터·K-Startup, config.json에 인증키가 있을 때만 (§7)
② WebFetch — 소스의 목록 URL을 열어 최근 게시물 파싱
③ WebSearch — "site:[도메인] 공고 [키워드] [YYYY년 M월]"
④ 실패 기록 — sources.py mark --result fail --note "사유", 브리핑 수집 현황에 표시
```

- 위 단계가 성공하면 아래 단계는 하지 않는다.
- `verified`가 F*이거나 목록이 비어 보이면 바로 ③으로 넘어간다. JS로 그려지는 목록은 WebFetch로 다시 열어도 비어 있다.
- 목록에서는 **최근 30일 이내 등록분** 중 접수 중이거나 곧 접수가 시작되는 것만 본다.
- 목록에서 게이트·A 판정 근거를 못 찾았는데 점수가 높을 것 같으면 상세 페이지를 1회 더 열어 신청 자격을 확인한다. 이것도 조회 1회로 센다.

---

## §3. 조회 예산과 순서

한 번의 전체 스캔은 **50회 이내**로 조회한다.

| 순서 | 범위 | 소스당 | 상한 |
| --- | --- | --- | --- |
| 1 | Tier 1 (필수) 6개 | 2회 | 12회 |
| 2 | 우선 "상" | 1회 (실패 시 ③ 1회 추가) | 18회 |
| 3 | 사전조사 검색 (§4) | - | 6회 (남겨 둠) |
| 4 | 우선 "중" | 1회 | 남은 예산 (약 14회) |

- `sources.py plan`이 이 순서대로 소스를 늘어놓고, "하" 소스는 마지막 조회 후 7일이 지난 것만 넣는다.
- `method`가 `iris`인 소스(R&D를 IRIS가 커버)는 자체 사이트를 조회하지 않는다. 단 `presurvey`가 true면 §4 사전조사 확인 때만 연다.
- 50회에 도달하면 남은 소스는 `mark`하지 말고 브리핑에 "미조회"로 남긴다.

## §4. 사전조사(수요조사·RFP 공개) 찾기

사전조사는 별도 목록 페이지가 없는 기관이 많아서, 공모와 같은 목록에서 제목으로 골라내는 것과 검색을 같이 쓴다.

1. **공모 목록에서 골라내기 (추가 조회 없음)** — Tier 1~3을 조회하며 제목에 "수요조사", "RFP", "공개검증", "사전공고", "사전규격", "기획 사전조사", "과제 발굴", "설명회"가 있으면 `presurveys`로 보낸다. NTIS·IRIS·경북TP·KEITI 목록에 자주 섞여 나온다.
2. **검색 (6회)** — 아래 검색어를 이번 달·다음 해 기준으로 바꿔 쓴다.

| 회 | 검색어 예 |
| --- | --- |
| 1 | `"기술수요조사" 2027 산업통상부` |
| 2 | `"기술수요조사" 2027 (수소 OR 이차전지 OR 바이오 OR 제조AI)` |
| 3 | `"RFP" "공개검증" OR "사전공개" 2027 신규과제` |
| 4 | `site:keit.re.kr 수요조사` 또는 `site:ketep.re.kr 수요조사` (presurvey 소스 중 이번에 안 연 곳) |
| 5 | `"수요조사" 경상북도 OR 포항 2027` |
| 6 | 나라장터 사전규격 (API 키가 있으면 API, 없으면 `"사전규격" 연구용역 테크노파크`) |

3. 찾은 사전조사도 실존 원칙을 똑같이 지킨다. 검색 결과 요약만 보고 담지 말고, 공고 페이지나 신뢰할 만한 기관 게시글에서 제목과 마감을 확인한다.

## §5. 자동 추가 규칙

포털이나 검색에서 찾은 공고의 원문이 `sources.json`에 **없는 기관**의 사이트에 있을 때, 아래를 모두 만족하면 그 기관을 소스로 추가한다.
포털이 늦게 싣거나 아예 안 싣는 기관 공고를 다음 스캔부터 직접 보기 위해서다.

1. 그 공고가 게이트를 통과했거나(점수 대상), 사전조사 관련도 "상"이다.
2. 원문 도메인이 기존 소스 도메인과 다르다 (`sources.py add`가 도메인 중복을 거부한다).
3. 그 기관의 **공고 목록 페이지**를 찾아 WebFetch로 열었고, 2개월 이내 게시물이 보인다. 목록을 못 찾으면 추가하지 않고 브리핑에 "소스 후보"로만 적는다.
4. 이번 스캔에서 자동 추가가 3개 미만이다. 이 확인에 쓴 조회도 50회 예산에 들어간다.

추가할 때 값: `--origin auto --priority 하 --tier 2`(지자체·지역기관이면 3), `--verified F`, `--fields`는 그 공고의 분야.
자동 추가 소스는 3회 연속 실패하면 `mark`가 스스로 비활성화한다. 사용자가 원치 않으면 `remove`로 지운다.

## §6. 중복·마감·실패 처리

- **중복 병합** — 같은 공고가 여러 소스에 나오면 공고번호, 없으면 공고명+기관으로 한 건으로 합친다. 링크는 전담기관 원문 → IRIS → 포털 순으로 고른다.
- **이력** — 이미 `history.json`에 있는 공고도 접수 중이면 결과에 넣는다. 렌더러가 처음 본 공고에만 NEW를 단다.
- **마감** — 스캔일 기준 마감이 지난 공고는 `closed`에 넣는다 (브리핑 본문 제외, 이력만 기록). 접수 시작 전인 공고는 접수 중과 같이 다루고 메모에 "접수 ○월 ○일부터"를 적는다.
- **포항TP 자체 공고** — `monitor_only` 소스의 공고는 채점하지 않는다.
- **실패 기록** — 조회한 소스는 성공·실패 모두 `sources.py mark`로 남긴다. 실패 사유는 짧게 쓴다(예: "JS 렌더링", "목록 갱신 멈춤(2026-08)", "인코딩 깨짐", "API 키 없음").

## §7. 공공데이터포털 API

| 소스 | API | data.go.kr 데이터 번호 |
| --- | --- | --- |
| e나라도움 국고보조 공모 | `https://apis.data.go.kr/1051000/MoefOpenAPI2025` | 15156853 |
| 나라장터 입찰공고·사전규격 | `https://apis.data.go.kr/1230000/ad/BidPublicInfoService02` | 15129394 |
| K-Startup 사업공고 | `https://apis.data.go.kr/B552735/kisedKstartupService02` | 15125364 |

- 인증키는 작업 폴더 `config.json`의 `api_keys.data_go_kr`에 둔다. 키가 없으면 ③ WebSearch로 대체하고 브리핑 수집 현황에 "API 키 없음"을 남긴다.
- 키 값은 채팅·브리핑·로그·results JSON 어디에도 적지 않는다. 직원마다 자기 키를 받아 쓰는 것을 전제로 한다.
- 오퍼레이션 이름과 파라미터는 각 API의 data.go.kr 상세 페이지에서 확인한 뒤 쓴다. 기억에 의존해 파라미터를 지어내지 않는다.
