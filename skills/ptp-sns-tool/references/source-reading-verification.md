# 원문 판독과 공식 대체본 검증

## 1. 다운로드와 판독 상태 분리

수집기의 종료코드·파일 확장자·해시 일치는 파일 확보 근거이며 본문을 읽었다는 근거가 아니다. 원본 `source.json`과 첨부는 보존하고 작업의 `reading-evidence.json` 또는 `facts.json.reading_evidence`에 파일별 판독 상태를 남긴다. 이 기록은 운영 근거이며 현재 수집기가 해당 판독을 자동 수행한다고 설명하지 않는다.

| 기록 | 남길 값 |
|---|---|
| 원본 | 공식 상세 URL·공고 ID, 첨부 URL·로컬 경로·SHA-256 |
| 다운로드 | 성공·실패, 수집 시각 |
| 판독 | `read`, `partial`, `unread`, `protected-distribution` 중 실제 상태 |
| 판독 근거 | 사용한 정상 열람·추출 수단, 읽은 쪽·구간, 렌더 확인 범위, 미판독 구간 |
| 대체본 | 사용 여부, 실제 읽은 파일·공식 출처·동일 공고 대조 근거 |

HWPX에서 본문 XML을 읽을 수 없으면 패키지의 manifest와 메타데이터에 `encryption-data`, `hpf:distribution` 같은 표시가 있는지 확인한다. 배포 표시와 암호화 표시를 각각 기록하며 표시 하나만으로 모든 본문이 암호화됐다고 단정하지 않는다. 보호된 배포 문서로 본문을 읽을 수 없다면 `protected-distribution`으로 남긴다. 파일이 손상됐거나 형식을 판별하지 못했으면 그 오류를 `unread` 사유로 기록한다.

지원되는 문서 앱의 정상 열람은 가능하지만 보호해제·암호 해독·비밀번호 추측·권한 우회는 하지 않는다. 미리보기나 표지에 사업명이 보이는 것만으로 모집조건 전체를 확인했다고 쓰지 않는다. 읽을 수 있는 공식 대체본을 찾는 동안 기존 파일과 나머지 검증 작업은 계속한다.

## 2. 공식 동일 공고의 대체본 사용

포항TP의 다른 공개 형식, 기업마당 등 공공기관의 공식 재게시 페이지·첨부·본문출력 PDF를 우선 확인한다. 검색 결과 요약·캐시·민간 재게시 글만으로 확정하지 않는다. 외부 페이지를 찾았다는 이유만으로 같은 공고로 채택하지 않는다.

1. 대체 게시처의 공식 출처 여부와 **원문 바로가기**를 확인한다. 링크가 작업의 PTP `board_idx`를 가리키는지 기록한다. 다른 모집차수·다른 연도의 글이면 채택하지 않는다.
2. 공고번호, 제목·사업연도, 공고일, 접수 시작·마감과 시각, 주관기관을 원본 상세·공개 표지·포스터와 대조한다. 등록일·공고일·접수 시작일은 서로 다른 항목으로 기록한다.
3. 두 게시처에 공통 첨부가 있으면 파일 크기와 SHA-256을 비교한다. 동일한 신청서 해시는 같은 배포 묶음을 뒷받침하지만 모집공고 본문 전체가 같다는 단독 증명은 아니다. HWPX와 변환 PDF처럼 형식이 다른 파일의 해시가 같을 것을 요구하지 않는다.
4. 대체 PDF의 전체 텍스트와 핵심 표·대상·금액·접수방법 페이지의 렌더를 확인한다. 최신 정정·취소·첨부 교체 여부도 원 게시처에서 대조한다. 읽지 못한 쪽이나 불일치는 따로 남긴다.
5. `alternative-source-evidence.json` 등에 원본·대체 상세 URL, 대체 파일 URL/경로/해시, 확인 시각, 항목별 일치·불일치·확인불가, 공통 첨부 해시, 실제 읽은 페이지, 채택 이유를 기록한다. `facts.json`에는 실제 읽은 **대체 PDF의 페이지**를 출처로 쓰고 원본 공고 URL을 함께 연결한다.

공식 원문 연결과 식별 항목·모집조건을 대조해 동일성이 확인되고 핵심 사실을 읽었다면 그 범위를 명시하고 제작을 계속한다. 원 HWPX의 판독 상태는 그대로 유지한다. 필수 조건에 해소되지 않은 차이가 있거나 유일한 근거를 읽지 못했으면 해당 주장을 확정하지 않는다. 대체본 탐색을 새로운 사용자 승인 단계로 만들지 않는다.

## 3. 금액·기간·신청방법 대조

`facts.json`의 각 값은 출처 페이지·표의 행/열과 연결한다. 숫자만 추출하지 않고 그 숫자가 누구에게, 어떤 기간에, 어떤 조건으로 적용되는지 함께 확인한다.

| 구분 | 확인 사항 |
|---|---|
| 지원금 | 국비·지방비 등 지원금의 성격, 기업당·과제당·컨소시엄당 구분, 확정액·한도·규모 표현 |
| 민간부담 | 최소 금액·비율, 현금·현물 구분, 현금 비율의 기준이 민간부담인지 총액인지 |
| 총사업비 | 지원금과 민간부담을 합한 규모인지, 단위와 합계가 맞는지; 전액 지원금으로 표현 금지 |
| 기간·연도 | 공고 연도·모집 대상 사업연도·수행기간·연간 규모·연차별 협약 구분; 다년 금액 보장 추정 금지 |
| 조건 | 부가세 포함 여부, 예산·평가·협약에 따른 변경 조건, 선정규모와 기초지자체별 제한 |
| 제출 경로 | 해당 공고의 온라인 URL·접수 이메일·방문 주소, 제출 주체와 정확한 마감 시각 |
| 제출서류 | 필수·해당 시·선택·가점 서류 구분; 선택 확인서를 필수로 바꾸지 않음 |

금액의 비율 기준이나 부가세 조건이 없으면 추정하지 않는다. 복잡한 금액 설명을 카드에서 생략할 수는 있지만, 금액을 표시한다면 필요한 부담·기간·변경 조건을 함께 전달한다. 선정·예산 편성·협약을 거치는 사업을 확정 지원으로 표현하지 않는다. 반대로 원문 근거 없이 ‘사전기획 단계’라고 바꾸지도 않는다.

홈페이지 경로·QR은 **공고 확인 수단**, 이메일·접수 시스템은 **제출 수단**이다. 온라인신청 버튼의 존재나 이전 공고의 CTA를 현재 접수방법의 근거로 쓰지 않는다. 이메일 접수 공고는 카드·캡션·대체텍스트에 확인된 이메일을 명시하고 QR은 `상세 공고 보기`로 구분한다. 부서명이 자료마다 다르면 공통으로 확인된 팀·공개 연락처를 사용하고 차이를 남긴다. 게시 직전에는 원 게시처의 접수상태·기한·정정·첨부 교체를 다시 확인한다.

## 검증 사례: 2026-10-22 공고 8189

[PTP 8189](https://www.ptp.or.kr/main/board/view.do?menu_idx=116&manage_idx=15&board_idx=8189)의 배포용 HWPX를 읽지 못했을 때 [기업마당 동일 공고](https://www.bizinfo.go.kr/sii/siia/selectSIIA200Detail.do?pblancId=PBLN_000000000127330)의 본문출력 PDF를 사용했다. 원문 바로가기의 PTP ID, 공고번호 2026-255·제목·공고일·표지와 공통 신청서의 동일 해시를 대조하고 PDF 6쪽을 확인했다. 원 HWPX는 미판독 상태로 보존했다.

이 공고는 2027년 신규과제이며 연간 컨소시엄당 지원 3.5억원, 민간부담 1.2억원 이상, 총 4.7억원 규모를 구분해야 했다. 접수는 2026-11-05 낮 12:00까지 이메일로 진행하므로 기존 공고의 홈페이지 온라인신청 문구를 재사용할 수 없었다. 이는 당시 대조 사례이며 다음 공고의 금액·기간·접수방법 기본값으로 사용하지 않는다.
