# 포항TP 보도자료 작성

## 핵심 원칙

- 확인된 사실만 단정적으로 작성하라.
- 누락된 사실을 추정하지 말고 `[확인 필요: 항목]`으로 표시하라.
- 과거 보도자료의 원장명, 담당자, 연락처, 일정, 수치, 사업명을 현재 사실처럼 재사용하지 말라.
- 행사·사업은 주최·주관·후원 등 기관별 역할을 확인하고 본문에 명시하라.
- 제목과 부제목을 한 조합으로 설계해 핵심 보도내용을 분명히 전달하라. 의미는 제목에 자연스럽게 담길 때만 넣고, 억지로 결합하지 말라.
- 첫 리드에서 행위 주체를 새로 제시할 때는 `이/가`를 사용하라. `포항테크노파크(원장 [성명], 이하 포항TP)가`를 기본 문형으로 삼아라.
- 완성형 본문은 `❍` 문단 6개 이상으로 구성하라. 기본은 6~8개이며, 분량을 맞추려고 같은 사실을 쪼개거나 반복하지 말고 리드·목적과 기관 역할·세부 내용·대상 효과·신청 또는 후속 정보·원장 인용을 각각 독립된 정보로 전개하라.
- 홍보성 수식보다 구체적인 행동, 성과, 수치, 지역·산업 효과를 앞세워라.
- 원문의 오탈자와 비문은 답습하지 말고 자연스러운 공공기관 보도문으로 교정하라.
- 일반 작성 안내와 포항TP 내부 교육자료가 다르면 내부 교육자료와 등록 양식을 우선하라.

## 필수 입력

보도자료 작성 전에 현재 요청과 첨부자료에서 다음 다섯 항목을 먼저 확인하라.

- 포항테크노파크 원장명
- 담당자 성명
- 소속 부서·팀
- 전화번호
- 이메일

현재 사용자가 알려준 원장명 기본값은 `송경창`이다. 다만 인명은 바뀔 수 있으므로 보도자료마다 입력된 원장명을 확인하고, 입력이 없으면 `원장명은 현재 기본값인 송경창으로 적용할까요?`라고 확인한 뒤 사용하라. 사용자가 현재 원장명을 이미 명확히 제시했으면 다시 묻지 않는다.

다섯 항목이 모두 있으면 다시 묻지 말고 그대로 사용하라. 하나라도 없으면 누락된 항목만 한 번에 질문하고 답변을 기다린 뒤 작성하라. 다섯 항목이 모두 없으면 다음처럼 묻는다.

`보도자료 작성 정보를 알려주세요: 원장명(현재 기본값: 송경창) / 담당자 성명 / 소속 부서·팀 / 전화번호 / 이메일`

- 직급은 선택 항목으로 받고, 제공된 경우에만 표시하라.
- 전화번호와 이메일 형식이 불완전하면 임의로 고치지 말고 재확인을 요청하라.
- 사용자가 본문 전용 초안이나 자리표시자 사용을 명시적으로 요청한 경우에만 필수 입력 없이 진행하라. HWPX 최종 파일은 다섯 항목을 모두 확인한 뒤 생성하라.
- 담당자 정보는 해당 보도자료 헤더 작성에만 사용하고 스킬 문서나 예시 데이터에 고정 저장하지 말라.
- 헤더에는 `담 당 자  [소속 부서·팀] [성명] [직급] ([전화번호], [이메일])` 순으로 표시하라.
- 원장명은 고정값으로 간주하지 말고, 해당 보도자료에 확인된 이름만 본문과 인용문에 사용하라.

## 계획안 파일·이미지 입력

사용자가 계획안·행사 개요·사업자료를 파일 또는 이미지로 첨부하고 `보도자료 작성해줘`라고 요청하는 방식을 기본 입력 유형으로 처리하라.

- 사용 가능한 문서·이미지 읽기 기능으로 첨부자료를 먼저 확인하고, 사용자가 내용을 다시 옮겨 적도록 요구하지 말라.
- 표, 도표, 각주, 이미지 안의 글자까지 읽어 사실 카드를 만들되, 판독이 불분명한 글자·수치·기관명은 추정하지 말고 `[확인 필요: 항목]`으로 표시하라.
- 여러 첨부자료의 내용이 다르면 최신본·최종본 표시와 작성일을 우선 검토하고, 충돌하는 사실은 사용자에게 확인하라.
- 첨부 이미지가 흐리거나 일부가 잘려 핵심 사실을 확인할 수 없을 때만 더 선명한 파일이나 누락 페이지를 요청하라.
- 파일·이미지에서 확인한 정보도 제목·부제목 선택, 본문 작성, HWPX 생성의 동일한 검수 절차를 적용하라.

## 주최·주관·후원

행사·사업 보도자료는 주최·주관·후원 기관을 조건부 필수 사실로 취급하라.

- 주최, 주관, 후원, 공동주최, 공동주관, 협력, 운영대행의 공식 명칭과 역할을 각각 확인하라.
- 협약기관이나 참여기관이라는 이유만으로 주최·주관·후원 역할을 추정하지 말라.
- 전년도 행사 역할을 현재 행사에 재사용하지 말라.
- 초안에서 확인되지 않은 역할은 `[확인 필요: 주최기관]`, `[확인 필요: 주관기관]`, `[확인 필요: 후원기관 또는 후원 없음]`으로 표시하라.
- 후원기관이 없으면 입력 단계의 사실카드에만 `후원 없음`을 기록하라. 본문에는 `후원 없이 추진됐다`, `후원기관은 없다`, `후원 없음`처럼 후원이 없다는 사실을 쓰지 말고 후원 관련 절 전체를 생략하라.
- 두 번째 문단에 `이번 행사는 [주최]가 주최하고 [주관]이 주관하며, [후원]의 후원으로 추진된다`와 같이 공식 역할을 명시하라.
- 주최·주관·후원은 실제로 존재하는 역할만 자연스럽게 연결한다. 세 역할을 모두 억지로 나열하거나, 확인되지 않은 주관기관을 문장에 추가하지 않는다. 후원이 없으면 `포항시가 주최하고 포항TP가 주관했다`처럼 존재하는 역할만 적는다.
- 리드에는 `포항TP가 [주최기관] 주최와 [후원기관] 후원으로 [행사명]을 개최할 예정이라고 밝혔다`처럼 배경 역할을 함께 넣을 수 있다.
- 취지 문단에는 `이번 행사는 [목적]을 위해 마련됐으며, [주최기관]이 주최하고 [후원기관]이 후원한다`처럼 별도 문장으로 정리할 수 있다.
- 기관명이 둘 이상이면 `경상북도와 포항시가 주최하고 포항국제전시컨벤션센터(POEX)가 후원한다`처럼 조사와 호응을 정확히 맞춘다. 중복 쉼표, `행사가 개최할 예정이다` 같은 비문, `가 … 가`가 과도하게 겹치는 문장은 피한다.
- 배포용 최종본은 적용되는 모든 역할을 확정한 뒤 작성하라.

## 제목·부제목

제목과 부제목을 본문보다 우선해 검수하라. 세부 기준은 [제목·부제목 설계 프레임워크](references/headline-subtitle-framework.md)와 [문체 가이드](references/style-guide.md)의 제목 부분을 따른다.

- 제목과 부제목을 함께 읽었을 때 `무슨 일이 있는가`가 분명해야 한다. 제목이 사실을 직접 말하면 부제목에서 의미와 근거를 더하고, 제목이 현장감·변화·독자효익을 앞세우면 부제목에서 공식 행사명과 핵심 행동을 명확히 한다.
- 보도자료 유형과 가장 강한 뉴스 요소에 따라 공식 행동·사실, 수치·성과, 대상·독자 효익, 변화·전환, 현장·장면, 시점·기회, 질문·답변, 대비·결합, 고유명사, 기관 책임·행동 가운데 사실로 뒷받침되는 관점군을 선택하라. 모든 보도자료를 `기관명 + 행동 + 의미` 구조로 만들지 말라.
- 기관명이 뉴스의 책임 주체나 신뢰성을 설명할 때만 제목에 넣는다. 행사명·성과·독자효익이 더 중요한 경우 제목에서 `포항TP`를 생략할 수 있다.
- 사실 카드를 바탕으로 제목·부제목 조합을 내부적으로 7개 이상 만든다. 적용 가능한 서로 다른 관점군 5개 이상으로 분산하고, 같은 시작어·끝맺음·`잇는다`, `강화`, `앞당긴다` 같은 상투어를 반복하지 않는다.
- 내부 후보는 사실 정확성·뉴스 명확성·구체성·독자 관련성·후보 차별성·간결성·제목과 부제목의 보완성을 각각 0~2점으로 평가한다. 치명적 결함이 없고 14점 만점에 11점 이상인 후보 가운데 가장 높은 한 안만 추천한다.
- 어순만 바꾸거나 동의어만 교체한 후보는 의미상 같은 안으로 보고 하나를 버린다. 사용자 제안안에서는 같은 기관명·주어로 시작하는 제목과 같은 끝맺음을 쓰는 제목을 각각 최대 2개로 제한한다.
- 부제목은 1~2줄로 작성하라. 첫 줄에는 제목에서 빠진 공식 행사·사업 내용이나 일시·장소를, 둘째 줄에는 규모·대상·핵심 프로그램·성과를 우선한다.
- 화면과 HWPX에서 부제목 각 줄은 앞에만 `- `를 붙이고 문장 끝에는 ` -`를 붙이지 않는다.
- 제목 문구를 부제목에서 반복하지 말고 숫자·대상·프로그램 등 새로운 정보를 더하라.
- `새로운 도약`, `미래를 연다`, `경쟁력 강화`처럼 어느 사업에도 붙일 수 있는 표현은 구체적인 변화가 확인되지 않으면 사용하지 말라.
- 과장, 선정적 표현, 근거 없는 기대효과, 본문에 없는 수치를 넣지 말라.

## 제목·부제목 선택 단계

새 보도자료를 작성할 때는 제목을 임의로 확정하지 말고 사용자가 방향을 선택할 수 있게 하라.

1. 필수 입력과 사실 카드를 확인한 뒤 [제목·부제목 설계 프레임워크](references/headline-subtitle-framework.md)에 따라 서로 다른 관점군 5개 이상에서 제목·부제목 조합을 내부적으로 7개 이상 만든다.
2. 이 가운데 차이가 분명한 제목·부제목 조합 3개를 기본으로 제안한다. 뉴스 요소가 풍부해 선택 가치가 있으면 최대 5개까지 제안할 수 있다.
3. 사용자에게 보이는 안은 관점군을 최소 3개 이상 포함하고, 같은 기관명·주어로 시작하는 제목과 같은 끝맺음을 쓰는 제목은 각각 최대 2개로 제한한다. 사실이 허용하면 기관명을 생략한 안과 수치·대상·현장·시점 가운데 하나를 앞세운 안을 각각 포함한다.
4. 각 안에 `공식 행동·사실`, `수치·성과`, `대상·독자 효익`, `현장·장면`, `기관 책임·행동` 등의 관점군을 표시하고, 품질 평가에서 가장 적합한 한 안에만 `(추천)`을 붙인다.
5. 모든 안에는 완성된 제목과 부제목 1~2줄을 함께 제시한다. 제목만 제안하거나 하나의 부제목을 여러 제목에 공통으로 붙이지 않는다.
6. 사용자에게 제시하기 전에 `scripts/check_headline_options.py`로 후보의 개수·관점군·추천안·시작어·끝맺음·의미상 중복·제목과 부제목의 겹침을 점검한다. 경고가 나오면 사실관계를 바꾸지 않는 범위에서 다시 선별하고 다듬는다.
7. `추천은 1안입니다. 사용하실 번호를 알려주세요. 제목은 2안, 부제목은 1안처럼 조합하거나 문구 수정을 요청하셔도 됩니다.`와 같이 선택 방법을 안내한다.
8. 사용자가 선택하기 전에는 보도자료 본문이나 HWPX 파일을 작성하지 말고 답변을 기다린다.
9. 사용자가 번호를 선택하면 해당 제목·부제목을 그대로 사용해 본문을 작성한다. 조합이나 문구 수정을 요청하면 그 내용을 반영하고, 뜻이 명확하면 다시 확인하지 말고 본문 작성으로 진행한다.

다음 경우에는 선택 단계를 생략할 수 있다.

- 사용자가 제목과 부제목을 확정 문구로 직접 지정한 경우
- 사용자가 `제목은 추천안으로 알아서 선택`, `제목 선택 없이 바로 작성`처럼 선택을 명시적으로 위임한 경우
- 기존 제목이 포함된 보도자료의 단순 맞춤법·문장 교정만 요청한 경우

사용자가 HWPX 파일을 처음부터 요청했더라도 제목·부제목 선택을 먼저 받고, 선택된 조합으로만 파일을 생성하라.

## HWPX 후속 제안

완성형 보도자료 본문을 화면에 제공한 응답의 마지막에는 다음 문장을 그대로 붙여 HWPX 생성 여부를 확인하라.

`보도자료 작성이 완료되었습니다. 배포양식에 맞춘 HWPX 파일도 작성할까요?`

- 제목·부제목 제안 단계, 필수 정보 확인 단계, 제목·문장 일부만 교정한 응답에서는 이 질문을 하지 말라.
- 사용자가 `네`, `작성해줘`, `HWPX로 만들어줘`처럼 동의하면 확정된 제목·부제목·본문·원장명·담당자 정보·기관 역할을 다시 묻지 말고 그대로 사용하라.
- HWPX 헤더나 최종본에 꼭 필요한 정보가 아직 없으면 누락 항목만 한 번에 확인한 뒤 즉시 파일을 생성하라.
- 사용자가 거절하면 HWPX를 생성하지 않고 작업을 마쳐라.
- 사용자가 처음부터 HWPX·한글문서·배포양식 파일까지 요청한 경우에는 완성형 본문 뒤에 이 질문을 반복하지 말고, 제목·부제목 선택과 필수 사실 확인이 끝나는 즉시 HWPX를 생성하라.

## 문장 연결과 흐름

사실 카드를 항목 순서대로 이어 붙이지 말고, 독자가 앞 문장에서 생긴 질문의 답을 다음 문장에서 자연스럽게 얻도록 구성하라.

- 전체 흐름은 `핵심 소식 → 추진 배경·목적과 기관 역할 → 구체적 내용·수치 → 대상이 얻는 효과 → 원장 인용·향후 방향`을 기본으로 한다.
- 각 `❍` 문단에는 하나의 중심 메시지를 두고, 다음 문단은 앞 문단을 반복하지 말고 이유·구체화·효과·후속 정보 중 하나를 더한다.
- 한 문장에 여러 사실을 쉼표와 `~하며`, `~하고`로 계속 연결하지 않는다. 주된 사실을 먼저 완결한 뒤 부연 설명은 다음 문장으로 나눈다.
- `이번 행사는`, `포항TP는`, `행사에서는`처럼 같은 표현으로 연속 문단을 시작하지 않는다. 주체가 이미 분명하면 생략하거나 `이를 위해`, `특히`, `아울러`, `한편` 등 문장 관계에 맞는 연결 표현을 선택한다.
- 연결 표현은 논리 관계가 있을 때만 쓴다. `이를 위해`는 목적에 따른 수단, `특히`는 핵심 내용의 강조, `아울러`는 같은 비중의 추가 정보, `한편`은 관련 사업·후속 일정으로 전환할 때 사용한다.
- 주어가 바뀌면 새 주체를 분명히 밝히고, 같은 주어가 이어지면 불필요하게 반복하지 않는다. 주어와 서술어, 능동·피동, 완료·예정 시제를 끝까지 호응시킨다.
- 초안이 완성되면 인접한 두 문단씩 이어 읽는다. 문단 사이에 `왜`, `어떻게`, `그래서 무엇이 달라지는가`에 대한 연결이 없으면 문장 순서나 표현을 다시 다듬는다.
- 세부 예시와 교정 기준은 [문체 가이드](references/style-guide.md)의 `문장 연결과 문단 흐름`을 따른다.

## 원장 인용문

사용자가 실제 인용문을 주지 않아도 확인된 보도자료 내용을 바탕으로 원장 인용문 초안을 작성하라.

- 1~2문장으로 작성한다.
- 앞부분에는 행사·사업의 취지, 목적 또는 대상에게 주는 효과를 담는다.
- 뒷부분에는 포항TP의 추진 방향, 지원 의지 또는 지역·산업 차원의 의미를 담아 마무리한다.
- 본문에 없는 수치, 성과, 약속, 신규 사업 또는 확정되지 않은 계획을 인용문에 추가하지 않는다.
- 실제 발언처럼 자연스럽게 쓰되 내부 검토용 초안임을 전제로 한다.
- 사용자가 확정 인용문을 제공하면 의미를 바꾸지 않는 범위에서 문장만 다듬는다.
- 최종본에는 확인된 원장명과 `말했다`, `밝혔다`, `강조했다` 등의 귀속 표현을 반드시 넣는다.

## 작업 순서

1. 원장명과 필수 담당자 입력 네 항목을 확인하고, 누락됐으면 먼저 입력받는다.
2. 사용자 자료에서 사실 카드를 만든다.
   - 배포일시, 보도일시, 담당부서, 붙임자료
   - 주체, 일시, 장소, 대상, 행동, 목적
   - 주최·주관·후원·공동기관·협력기관·운영대행·재원
   - 참여·예산·기간·교육시간·성과 등 핵심 수치
   - 확인된 원장명과 제공된 인용문 또는 인용문에 사용할 근거
   - 신청 방법, 향후 계획, 관련 사업
3. 작성 전 [통합 작성 원칙](references/general-writing-principles.md), [문체 가이드](references/style-guide.md), [제목·부제목 설계 프레임워크](references/headline-subtitle-framework.md)를 읽고 보도자료 유형과 핵심 뉴스 한 문장을 정한다.
4. 서로 다른 관점군 5개 이상에서 제목·부제목 조합 7개 이상을 내부적으로 만든다. 품질 평가와 의미상 중복 제거를 거친 뒤 [출력 템플릿](references/output-template.md)의 선택 형식으로 차이가 분명한 조합 3~5개를 제안한다.
5. 사용자가 선택하거나 선택을 위임할 때까지 본문과 HWPX 작성을 멈춘다.
6. 선택된 제목·부제목을 확정한 뒤 본문을 6~8개의 `❍` 문단으로 구성한다. 첫 문단은 `포항테크노파크(원장 [성명], 이하 포항TP)가`처럼 `이/가`로 시작해 누가·언제·어디서·무엇을 했는지 짧게 쓰고, 두 번째 문단에 목적과 주최·주관·후원 역할을 명시한다. 이후 문단은 세부 내용·수치→대상 효과→신청·후속 정보→원장 인용 순으로 배치한다.
7. 원장 인용문은 이 스킬의 인용문 규칙에 따라 확인된 사실에서 작성한다.
8. 완성된 초안은 인접한 문단을 이어 읽으며 같은 주어·접속어·서술어의 반복, 과도하게 긴 문장, 사실의 단순 나열을 다듬는다.
9. 담당자 정보 이외의 누락 사실은 초안 작성이 가능하면 자리표시자로 표시하고, 초안 뒤에 확인 필요 목록을 짧게 제시한다.
10. 완성형 보도자료를 화면에 제공한 뒤, 사용자가 처음부터 파일을 요청한 경우가 아니면 `보도자료 작성이 완료되었습니다. 배포양식에 맞춘 HWPX 파일도 작성할까요?`라고 묻는다.
11. 사용자가 HWPX 생성을 요청하면 이미 확정된 내용을 재사용하고, 파일 생성에 꼭 필요한 누락 항목만 확인해 등록 양식으로 작성한다.
12. 최종본 요청이면 모든 자리표시자를 해소하고 담당자 정보·원장명·주최·주관·후원·수치·날짜·고유명사·인용문을 원자료와 대조한다.
13. 제목 제안안은 `python scripts/check_headline_options.py <제안안.json>`으로 먼저 점검한다. 텍스트 본문은 `python scripts/check_press_release.py <파일> --director-name "<확인된 원장명>"`로 점검한다. 행사·사업은 `--require-organizers`, 배포 가능한 최종본은 `--final`을 추가한다. 경고가 나오면 사실관계를 바꾸지 않는 범위에서 다시 선별·교정한다.

## 기본 출력

- 새 보도자료 작성 요청의 첫 응답에서는 제목·부제목 조합 3~5개만 제안하고 사용자 선택을 요청한다. 선택 후 두 번째 응답에서 바로 복사할 수 있는 완성형 한국어 보도자료를 제공한다.
- 필수 입력이 누락되면 질문을 먼저 하고, 답변 전에는 보도자료를 작성하지 않는다.
- 담당자 정보 외의 메타데이터가 없으면 본문을 멈추지 말고 `[확인 필요]`를 사용한다.
- 완성형 보도자료 본문은 기본 6~8개의 `❍` 문단으로 작성한다. 확인된 정보가 부족하면 사실을 반복해 문단 수를 채우지 말고 필요한 위치를 공란 또는 `[확인 필요]`로 남긴다.
- 초안 아래에는 확인이 필요한 사실만 나열한다. 일반적인 설명이나 작성 과정은 붙이지 않는다.
- 교정 요청이면 교정본을 먼저 제공하고, 의미가 달라진 핵심 수정만 짧게 요약한다.
- 제목·부제목 제안은 내부 후보 7개 이상을 서로 다른 관점군 5개 이상에서 만든 뒤, 의미와 구조가 겹치지 않는 3~5개를 골라 각 안에 맞는 부제목과 함께 제시한다.
- 완성형 보도자료를 제공한 응답은 확인 필요 목록 뒤에 `보도자료 작성이 완료되었습니다. 배포양식에 맞춘 HWPX 파일도 작성할까요?`라는 후속 질문으로 끝낸다.

## 문서 파일 처리

- 사용자가 `파일`, `HWPX`, `양식에 작성`을 요청하면 문단 분리와 내어쓰기가 반영된 등록 양식 `assets/pohang-tp-press-release-template-v2.hwpx`의 사본에 내용을 채워 `.hwpx`로 제공한다.
- 완성형 본문 뒤의 후속 질문에 사용자가 동의한 경우도 파일 요청으로 간주한다. 이때 앞 단계에서 확인된 내용을 다시 질문하지 않는다.
- 최초 요청에 HWPX 생성이 포함되어 있으면 완성형 본문 뒤에 생성 여부를 다시 묻지 않고 파일을 만든다.
- 파일 요청에서도 제목·부제목 선택이 먼저다. 사용자가 선택하거나 선택을 위임하기 전에는 JSON 입력과 HWPX 파일을 생성하지 않는다.
- 원본 양식과 사용자가 준 자료는 수정하지 않는다.
- [출력 템플릿](references/output-template.md)의 JSON 구조로 입력 파일을 만든 뒤 다음처럼 실행한다.

  `python scripts/fill_press_release_hwpx.py --template assets/pohang-tp-press-release-template-v2.hwpx --input <입력.json> --output <결과.hwpx>`

- 출력 파일이 이미 있으면 덮어쓰지 말고 새 이름을 사용한다.
- 생성 후 항상 `scripts/validate_hwpx.py <결과.hwpx>`로 자체 무결성 검사를 실행한다. HWPX 전용 스킬이 설치되어 있으면 해당 스킬의 `page_guard.py`도 추가로 실행한다.
- 본문의 각 `❍` 항목은 줄바꿈 문자가 아니라 독립된 HWPX 문단(`<hp:p>`)으로 생성한다. 여러 항목을 한 문단의 런에 합치지 않는다.
- HWPX 본문도 6~8개의 독립된 `❍` 문단으로 생성한다.
- 모든 `❍` 문단에는 양식의 본문 내어쓰기 문단 서식을 동일하게 적용해, 두 번째 줄부터 글자 시작 위치에 맞춰 정렬한다.
- 초안 HWPX에 `[확인 필요: …]` 문구가 남으면 해당 문구만 빨간색으로 표시한다. 같은 문단의 확인된 내용까지 빨간색으로 바꾸지 않는다.
- HWPX 텍스트를 치환하거나 문단을 추가한 뒤에는 이전 `linesegarray` 배치 캐시를 제거해 한글에서 새 내용에 맞게 줄바꿈과 행 높이를 다시 계산하도록 한다.
- 사진은 문서 안에 삽입하지 않는다. 사용자가 사진을 제공하면 원본 파일을 별도 첨부하도록 안내하고, 본문·사진 파일은 구분해 제공한다.
- `.hwp`는 바이너리 형식이므로 안전한 읽기·변환 경로가 확인된 경우에만 직접 처리한다.
- 문서 파일을 만들더라도 본문 사실 검증과 이 스킬의 문체 기준을 먼저 통과시킨다.
- HWPX의 부제목은 1~2줄을 지원한다. 두 줄이면 JSON의 `subtitle`에 문자열 배열을 사용한다.

## 실행 환경

- 실행 환경이 준비되지 않았으면(runtime-python.txt가 없고 lxml이 없는 경우) 사용자에게 스킬 폴더의 install_windows.bat을 한 번 실행하도록 안내한다.
- 배포본의 `install_windows.bat`로 설치한 경우 스킬 폴더의 `runtime-python.txt`에 기록된 Python을 우선 사용한다.
- `runtime-python.txt`가 없으면 Python 3.10 이상과 `lxml`이 설치된 실행 파일을 사용한다.
- 한컴오피스는 HWPX 생성의 필수 조건이 아니다. 설치되어 있으면 실제 열기·쪽수·출력 화면 검증에 추가로 사용한다.
