# 공지사항·사업공고 감시와 SNS 게시

포항TP 공식 공지사항은 관리번호 2, 사업공고는 관리번호 15다. 식별키는 각각 `ptp:2:<번호>`, `ptp:15:<번호>`다. SNS 게시 위임 범위 안에서만 실행한다. 스케줄러가 켜진 상태에서 30분마다 점검한다. KST와 실제 공개 시각을 사용한다.

## 후보와 2시간 대기

`python scripts/board_monitor.py --policy <운영폴더/board-monitor-policy.json>`을 매 실행 호출한다. 반환값의 `errors`가 비어 있는 게시판을 사용한다. 최초 목록을 기준으로 보존하며 이전 글을 자동 소급 홍보하지 않는다. 등록 날짜만 공개되므로 신규 항목은 첫 확인 시각부터 2시간을 기다린다. 확인 기록을 수정 시각이나 정확한 홈페이지 등록 시각이라고 표현하지 않는다. 공고 본문·첨부 정정은 기존 ID의 수정으로 보고 새 ID처럼 자동 재게시하지 않는다.

기존 미게시 계획에서 이관된 공고를 먼저 확인한다. 그다음 최초 발견 시각 순으로 새로운 공고를 검토한다. `window_block`이 있으면 기다리거나 원래 제출 결과를 확인한다. 이미 양 채널에 게시 또는 예약된 공고는 건너뛴다. 한 채널만 성공한 경우 같은 공고의 다른 채널을 먼저 확인한다. 새 공고의 작업 시작과 실제 제출은 앞 공고의 두 채널 중 늦은 실제 공개 시각으로부터 최소 2시간 후다. 정상 확인과 제작에 걸린 시간만큼 게시 시각은 늦어질 수 있다.

## 확인과 제출

- 선택 공고의 상세 제목·번호·공식 첨부를 실제로 대조한다. 사업공고는 접수 중, 마감까지 최소 72시간을 게시 직전 확인한다. 마감 시각이 없으면 간격 산정에 마감일 00:00을 보수적으로 사용하고 이미지·캡션에는 날짜만 쓴다. 7680처럼 기간 충돌로 보류한 건은 공식 정정 근거가 생기면 검토 결과를 보고한다. 통합공고는 세부 사업의 실제 신청 접수가 확인될 때 검토한다.
- 공지사항은 외부 독자에게 유효한 공개 안내만 게시한다. 일반 공개가 필요한 행사·이용 안내·중요 공지 등을 포함한다. 개인 정보, 명단·개별 합격 결과, 내부 업무, 종료된 안내, 별도 게시판의 입찰·채용은 자동 홍보 범위에서 제외한다. 신청형 공지는 사업공고와 같은 접수 중·72시간 조건을 적용한다. 링크가 삭제됐거나 정정·취소 여부가 불명확하면 보류한다.
- 실제 Meta 두 계정에서 게시물·예약·임시저장을 원문 번호, 제목, 연장·차수, QR 목적지 기준으로 대조한다. 8210은 기존 11월 5일 마감 게시물을 원래 모집으로 구분하고, 11월 12일 연장 공고가 미게시인 경우에만 연장 안내를 만든다. 조회가 로딩 중이거나 결과가 불확실하면 제출하지 않는다.
- 후보별로 별도 작업 폴더에 당일 한 공고 `plan.json`과 `daily-execution.json`을 만든다. 편성에는 `board_monitor`에 운영 정책 JSON의 절대경로, `schedule[0].manage_idx`에 게시판 번호, `minimum_remaining_days=3`을 기록한다. 같은 시각의 재시도는 기존 상태를 재사용한다. 기존 일정과 확정 패키지는 보존한다. 다른 실행이 foundation-meta를 점유하면 대기한다. `social_runtime.py select/begin`의 시간 검사와 직전 `submission-check`를 모두 사용한다.
- 사업공고의 `--eligibility`는 기존 양식 그대로 쓴다. 공지사항은 `source_key`, 모니터가 반환한 `source_url`, 현재 공개 상태를 확인한 `status=public-current`, `checked_at`, 다운로드한 공개 상세의 `detail_path`·`detail_sha256`, 확인한 마감 `deadline`과 `deadline_precision=day|datetime`을 쓴다. 신청 마감 자체가 없는 안내의 `deadline`은 null이다. 접수 중 여부, 첨부, 중복 조회 및 취소 확인 근거는 별도 증빙으로 보존한다. 증빙 시각은 게시 직전 30분 이내다.
- 승인된 테오·피오와 공용 1080×1080 PNG, 검증된 QR, 채널별 문안과 대체텍스트를 준비한다. `runtime_contract_version=1` 패키지로 검수하고, 실제 제출 전 대상 채널별 `submitting`을 기록한다. 인스타그램과 페이스북에 같은 공고를 같은 실행에서 각 한 건 올린다. 기존에 성공한 채널은 제외한다. 각 채널의 공개 링크·시각과 실제 이미지·문구·QR 확인 결과를 기존 시도에 기록한다.
