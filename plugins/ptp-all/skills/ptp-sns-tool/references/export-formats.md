# PNG·PDF·HTML 출력

## 공통 원칙

- 하나의 기준 레이아웃에서 플랫폼별 비율을 각각 재배치한다.
- 결과물 폴더에는 `source`, `preview`, `delivery`를 분리할 수 있다.
- 파일명은 `{job_id}_{platform}_{placement}_{page_no:02d}.{ext}`를 기본으로 한다. 플랫폼·지면 토큰을 생략해 여러 채널 파일이 덮어써지지 않게 한다.
- 가슴 `T/P`는 이미지 자산에 포함된 조형을 유지하고 Paperlogy로 덮지 않는다.
- 최종 크기는 [final-size-and-resolution.md](final-size-and-resolution.md)의 프로필로 잠근다. 디지털 픽셀과 인쇄 mm·DPI를 혼용하지 않으며 완성된 저해상도 래스터를 확대하지 않는다.

## PNG

- SNS 업로드용 기본 산출물이다.
- RGB 또는 RGBA로 내보낸다. `channel-native-1x`는 프리셋 픽셀, `high-resolution-master-2x`는 2× 마스터와 1× 업로드본, `custom-pixel`은 지정 픽셀을 사용한다.
- 투명 배경은 채널이 허용하고 사용자가 요청한 경우에만 사용한다.
- `publication` 모드에서는 실제 픽셀, 색상 모드, 파일 크기, 해시를 검사한다.

## HTML

- 반응형 미리보기, 웹 배너 또는 편집 가능한 전달본에 사용한다.
- 카드 세트를 HTML 한 파일로 묶을 때는 각 카드 루트에 `data-card-page="1"`부터 연속 번호를 넣는다. 카드별 HTML 파일로 나누면 각 파일에는 해당 번호 하나만 둔다.
- `assets/fonts/paperlogy/paperlogy.css`를 불러오거나 배포 폴더에 폰트와 OFL을 함께 복사한다.
- 이미지에는 대체텍스트를 제공하고, 제목부터 CTA까지 DOM 읽기 순서를 시각 순서와 맞춘다.
- 단일 파일이 필요한 경우 이미지·폰트 포함 방식과 결과 용량을 기록한다. 외부 CDN은 사용자가 허용하지 않으면 쓰지 않는다.
- CSS 표시 크기만 바꾸어 저해상도 래스터를 확대하지 않는다. 반응형 영역에서도 원본 종횡비와 `srcset` 또는 목표별 자산 역할을 유지한다.

## PDF

- 디지털 검토본은 HTML 또는 조립 원본에서 페이지 크기를 고정해 내보낸다.
- SNS별 카드 수와 묶음 PDF 페이지 수를 일치시킨다. 카드별 PDF로 나누면 각 파일은 1쪽이어야 한다.
- 인쇄용 PDF는 디지털 PDF와 구분한다. 재단 크기, 도련, DPI, 색상 프로필과 인쇄소 요구사항이 없으면 `print-ready`라고 부르지 않는다.
- `print-production`은 mm와 DPI로 계산한 목표 픽셀을 사용하며 화면용 1× PNG를 확대해 삽입하지 않는다.
- `publication` 모드에서는 실제 페이지 렌더를 확인하고 글꼴 대체, 잘림, 빈 페이지와 링크 오류를 검사한다.

## 다중 형식 패키지

- 요청이 `PNG+PDF+HTML`이면 PNG 업로드본, 묶음 PDF 검토본, HTML 미리보기를 같은 문구 버전에서 생성한다.
- 세 형식의 제목·수치·날짜·연락처와 카드 순서가 같아야 한다.
- 형식 중 하나를 만들 도구가 없으면 빈 확장자 파일을 만들지 않고 `tool-dependent` 또는 `specification-only`로 보고한다.
