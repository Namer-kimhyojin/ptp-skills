# 포항TP 보도자료 출력 템플릿

## 필수 입력

보도자료 작성 전에 다음 다섯 항목을 확인한다.

- 원장명(현재 기본값 `송경창`, 문서마다 확인):
- 담당자 성명:
- 소속 부서·팀:
- 전화번호:
- 이메일:
- 직급(선택):

요청이나 첨부자료에 없는 항목만 한 번에 질문한다. 다섯 항목이 모두 없으면 아래 문장을 사용한다.

`보도자료 작성 정보를 알려주세요: 원장명(현재 기본값: 송경창) / 담당자 성명 / 소속 부서·팀 / 전화번호 / 이메일`

사용자가 현재 원장명을 이미 명확히 제시했으면 다시 묻지 않는다. 사용자가 본문 전용 초안 또는 자리표시자 사용을 명시하지 않은 한, 필수 입력을 받기 전에는 보도자료를 작성하지 않는다.

## 제목·부제목 선택 단계

새 보도자료 작성 요청에서는 내부적으로 서로 다른 관점군 5개 이상에서 제목·부제목 조합 7개 이상을 만든 뒤, 아래 형식으로 차이가 분명한 조합을 먼저 제안하고 답변을 기다린다. 기본은 3개이며 선택 가치가 분명할 때 최대 5개까지 제안한다.

```text
[제목·부제목 제안]

1. 공식 행동·사실 (추천)
   [제목]
   - [제목을 보완하는 일시·장소·공식 행동]
   - [규모·대상·프로그램·성과]

2. 대상·독자 효익
   [제목]
   - [이 제목에 맞춘 공식 행사·사업 내용]
   - [대상이 얻게 되는 구체적 효과와 근거]

3. 현장·장면
   [제목]
   - [이 제목에 맞춘 일시·장소·핵심 행동]
   - [현장 프로그램·참여 규모·성과]

추천은 1안입니다. 사용하실 번호를 알려주세요.
제목은 2안, 부제목은 1안처럼 조합하거나 문구 수정을 요청하셔도 됩니다.
```

- 각 안은 제목뿐 아니라 부제목까지 완성된 문장으로 작성한다.
- 부제목은 각 줄 앞에만 `- `를 붙이고 문장 끝에는 ` -`를 붙이지 않는다.
- `(추천)`은 한 안에만 표시한다.
- 사용자 제안안은 최소 3개의 관점군을 포함하고, 같은 기관명·주어 시작과 같은 끝맺음은 각각 최대 2개로 제한한다.
- 어순만 바꾸거나 동의어만 교체한 의미상 중복 후보를 함께 제시하지 않는다.
- 추천안은 14점 품질 평가에서 11점 이상이고 치명적 결함이 없는 조합으로 정한다.
- 사용자가 번호를 선택하거나 선택을 위임하기 전에는 완성형 본문과 HWPX를 만들지 않는다.
- 사용자가 조합을 요청하면 선택한 제목과 부제목의 조사·시제·중복 표현을 한 번 더 다듬은 뒤 본문에 적용한다.
- 사용자가 확정 제목·부제목을 직접 제공했거나 제목 선택을 명시적으로 위임하면 이 단계를 생략한다.

## 완성형 템플릿

```text
보 도 자 료

배포일시  [YYYY. M. D.(요일)]
보도일시  [배포 후 즉시 / YYYY. M. D.(요일)부터]
담당부서  [본부·센터·팀]
붙임자료  [참고자료 N부 / 사진 N매]
담 당 자  [소속 부서·팀] [성명] [직급] ([전화번호], [이메일])

[가장 강한 뉴스 요소에 맞춘 사실형·수치형·독자효익형·현장형·변화형·기관행동형 제목]
- [일시·장소·공식 행사 또는 사업 내용]
- [규모·대상·핵심 프로그램·정량 성과]

❍ [주체]이/가 [일시] [장소]에서 [대상·규모]를 대상으로 [핵심 행동]했다고 밝혔다.

❍ 이번 [행사·사업]은 [문제·배경]에 대응하고 [목적]하기 위해 마련됐다. [주최기관]이 주최하고 [주관기관]이 주관하며, [후원기관]의 후원으로 추진된다.

❍ 이를 위해 [프로그램·시설·서비스·시험범위의 구체적 내용]을 제공한다. [숫자와 단위가 포함된 범위·기간·규모]를 목표로 한다/달성했다.

❍ 특히 [앞 문단의 구체적 내용과 연결되는 핵심 지원·성과]를 통해 [참여자·기업·지역 산업이 얻게 되는 실질적 효과]를 높인다.

❍ [신청·이용 방법, 모집·운영 일정, 후속 계획 등 독자가 행동하는 데 필요한 정보].

❍ [확인된 원장명] 포항테크노파크 원장은 “이번 [행사·사업]이 [취지·목적·대상 효과]에 도움이 되길 바란다”며, “[확인된 추진 방향·지역 산업의 의미]를 위해 노력하겠다”고 말했다.

❍ 한편, [본문과 직접 관련된 별도 사업이나 추가 후속 일정이 있을 때만 선택적으로 추가].
```

## 작성 후 제공 형식

완성본 뒤에는 필요한 경우에만 다음을 붙인다.

```text
[확인 필요]
- [확정되지 않은 수치]
- [확정되지 않은 향후 계획]
- [현재 담당자·연락처]
```

최종본에서는 위 목록과 본문 자리표시자가 모두 없어야 한다.

## HWPX 후속 확인

사용자가 처음부터 HWPX·한글문서·배포양식 파일을 요청하지 않았다면, 완성형 보도자료와 확인 필요 목록을 제공한 뒤 아래 문장으로 응답을 끝낸다.

```text
보도자료 작성이 완료되었습니다. 배포양식에 맞춘 HWPX 파일도 작성할까요?
```

- 사용자가 동의하면 확정된 제목·부제목·본문·원장명·담당자 정보·기관 역할을 다시 묻지 않는다.
- 파일 생성에 꼭 필요한 미확정 정보가 있으면 누락 항목만 한 번에 확인하고, 답변을 받는 즉시 HWPX를 생성한다.
- 사용자가 거절하면 파일을 만들지 않는다.
- 최초 요청에 HWPX 생성이 포함되어 있으면 이 질문을 생략하고, 제목·부제목 선택과 필수 사실 확인이 끝난 뒤 바로 파일을 생성한다.
- 제목·부제목 제안, 입력 정보 확인, 제목만 작성, 문장 일부 교정처럼 완성형 보도자료를 제공하지 않은 응답에는 이 질문을 붙이지 않는다.

## HWPX 생성용 JSON

사용자가 파일을 요청하면 아래 구조로 UTF-8 JSON을 만든다. `body`는 선행 `❍` 없이 6~8개 문단으로 구성한다.

```json
{
  "release_date": "2026. 7. 28.(화)",
  "press_time": "배포 후 즉시",
  "department": "담당 본부·센터",
  "attachments": "관련사진 2매",
  "director_name": "확인된 원장명",
  "roles": {
    "host": "주최기관",
    "organizer": "주관기관",
    "sponsor": "후원기관 또는 없음",
    "cooperation": "협력기관 또는 없음",
    "operator": "운영대행기관 또는 없음"
  },
  "contact": {
    "team": "담당 부서·팀",
    "name": "담당자 성명",
    "title": "직급 또는 빈 문자열",
    "phone": "054-000-0000",
    "email": "name@example.org"
  },
  "title": "제목",
  "subtitle": [
    "일시·장소·공식 행사 또는 사업 내용",
    "규모·대상·핵심 프로그램·정량 성과"
  ],
  "body": [
    "누가·언제·어디서·무엇을 했는지 담은 리드",
    "행사·사업의 취지와 기관 역할",
    "일정·장소·대상·규모 등 운영 개요",
    "프로그램·지원 내용과 확인된 수치",
    "대상에게 주는 효과 또는 신청·이용 정보",
    "확인된 원장명과 함께 작성한 원장 인용문",
    "필요한 경우에만 추가하는 관련 사업·후속 일정"
  ]
}
```

- `director_name`은 본문의 원장 인용문에 같은 표기로 들어가야 한다.
- `title`과 `subtitle`에는 사용자가 선택하거나 선택을 위임한 조합만 입력한다.
- HWPX 출력에서는 `body` 배열의 각 항목을 하나의 독립된 `❍` 문단으로 생성하고, 모든 문단에 같은 내어쓰기를 적용한다.
- 초안의 `[확인 필요: …]` 문구는 해당 문구만 빨간색으로 표시한다.
- 행사·사업은 `roles`를 공식 자료와 대조하고 두 번째 본문 문단에 주최·주관·후원을 명시한다.
- `sponsor`가 `없음`이면 최종본문에서 후원 문구를 생략한다.
- `sponsor`가 `없음`이면 `후원 없이 추진됐다`, `후원기관은 없다`, `후원 없음`이라고 쓰지 않는다. `[주최기관]이 주최하고 [주관기관]이 주관했다`처럼 존재하는 역할만 적는다.
- `subtitle`은 문자열 한 개 또는 1~2개의 문자열 배열을 사용한다.
- `phone`과 `email`은 실제 담당자 정보로 교체하고 형식을 확인한다.
- 사진은 HWPX에 삽입하지 않고 원본 파일로 별도 첨부한다.
- 등록 양식의 제목·메타데이터·본문 서식을 유지한다.

## 제목 대안 형식

```text
1. 공식 행동·사실: [공식 행사·사업·성과] [개최·성료·모집·개소·확대]
2. 수치·성과: [핵심 수치], [확정된 결과·변화]
3. 대상·독자 효익: [대상]의 [구체적인 문제·부담] [줄인다·돕는다]
4. 변화·전환: [기존 방식·범위]에서 [확인된 변화]로
5. 현장·장면: [대조·현장 장면]…[행사·교육·서비스]
6. 시점·기회: [마감·개막·이용 개시 시점], [독자가 할 행동]
7. 질문·답변: [독자의 실제 질문]…[확인된 해결 행동]
8. 대비·결합: [교육과 현장·기술과 사업화 등 확인된 결합]
9. 고유명사·행사명: [직관적인 공식 명칭] [핵심 행동]
10. 기관 책임·행동: [기관], [책임 있는 행동·조치]

각 제목 아래에는 제목에서 빠진 공식 행사명·일시·장소·규모·대상·프로그램을
부제목 1~2줄로 보완한다.
```

## 빠른 검수

- 제목과 부제만 읽어도 무엇이 뉴스인지 알 수 있는가
- 제목과 부제목이 역할을 나눠 핵심 보도내용과 새로운 세부 사실을 전달하는가
- 내부 제목·부제목 후보가 7개 이상이고 서로 다른 관점군 5개 이상을 사용했는가
- 사용자 제안안이 최소 3개의 관점군으로 나뉘고 같은 기관명·주어 시작과 같은 끝맺음이 각각 2개를 넘지 않는가
- 어순·동의어만 바꾼 의미상 중복 후보가 없는가
- 추천안이 품질 평가 11점 이상이고 치명적 결함이 없는가
- `scripts/check_headline_options.py`의 기계적 다양성 점검을 거쳤는가
- 사용자가 제목·부제목 조합을 선택했거나 선택을 명시적으로 위임했는가
- 완성형 본문 뒤에 HWPX 생성 여부를 물었거나, 최초 요청에 따라 HWPX를 바로 생성했는가
- `❍` 본문이 6개 이상이며 각 문단이 서로 다른 정보를 담는가
- 첫 문단에 주체·시점·행동·결과가 있는가
- 첫 리드의 주체가 `이/가`로 연결됐고, `포항테크노파크(원장 [성명], 이하 포항TP)가` 문형을 따르는가
- 본문 문단마다 새로운 정보가 하나씩 있는가
- 문단이 핵심 소식→목적·역할→세부 내용·수치→실질적 효과→향후 방향으로 이어지는가
- 인접한 문단이 같은 주어·시작 표현·서술어를 반복하지 않는가
- 한 문장에 쉼표와 `~하며`, `~하고`를 사용해 여러 사실을 과도하게 연결하지 않았는가
- 수치에 출처가 있고 단위가 일관적인가
- 행사·사업의 주최·주관·후원이 공식 역할대로 명시됐는가
- 원장명과 담당자 성명·소속 부서/팀·전화번호·이메일이 모두 있고 현재 정보인가
