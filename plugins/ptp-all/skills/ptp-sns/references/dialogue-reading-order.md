# 대사 읽기 순서

모든 웹툰·대화형 카드뉴스의 콘티, 생성 프롬프트, 최종 이미지 검수에서 적용한다. 페이지 넘김과 컷 순서인 `reading_direction`만으로 말풍선 순서까지 확인했다고 보지 않는다.

## 두 가지 배치 중 하나

- **왼쪽→오른쪽 (`left-to-right`)**: 같은 행에 놓인 말풍선을 발화 순서대로 배치한다. 먼저 말하는 풍선이 왼쪽, 다음 풍선이 오른쪽이다. 높이 차이 때문에 오른쪽 풍선이 먼저 읽히지 않도록 같은 읽기 띠 안에 정렬한다.
- **위→아래 (`top-to-bottom`)**: 먼저 말하는 풍선을 위에, 다음 풍선을 확실히 아래에 둔다. 좌우 배치보다 세로 순서가 먼저 인지되도록 충분히 분리한다. 나란히 경쟁하는 풍선을 만들지 않는다.

한 컷 또는 끊김 없이 이어지는 대화 묶음에서는 한 가지 방향을 선택한다. 왼쪽에 답변·오른쪽에 질문을 두고 질문을 조금 높이는 식으로 두 순서를 충돌시키지 않는다. 대각선·지그재그 이동, 풍선 꼬리 추적, 번호·화살표로 잘못된 배치를 해독하게 만들지 않는다. 방향 전환이 필요하면 명확한 컷 테두리·거터로 대화 묶음을 나눈다. 새 컷에서 방향을 바꾸더라도 컷 사이의 순서는 분명해야 한다.

인물의 기존 좌우 위치보다 발화 순서가 우선이다. 대화축을 보존해야 하면 첫 질문과 답변을 위아래 별도 컷으로 나누거나 클로즈업을 사용한다. 인물 위치를 이유 없이 뒤집지 않는다. 말풍선의 꼬리는 정확한 화자에만 연결한다. 독백·생각 풍선·내레이션이 사건 이해 순서에 영향을 주면 함께 순서를 정한다.

## 콘티와 생성 명세

컷마다 `dialogue_flow`와 번호가 있는 `dialogue_order`를 작성한다. 예:

```json
{
  "panel": 1,
  "dialogue_flow": "top-to-bottom",
  "dialogue_order": [
    {"order": 1, "speaker": "상담사", "text": "어떤 사업 하세요?", "placement": "upper"},
    {"order": 2, "speaker": "방문객", "text": "수산업이오.", "placement": "lower"}
  ]
}
```

이는 콘티·검수용 추가 필드이며 기존 CLI가 공간 배치를 자동으로 증명하는 기능은 아니다. 생성 프롬프트에도 순번·화자·정확한 문구·위치·선택 방향을 함께 전달한다. 말풍선 내부 여러 줄의 한글은 통상적인 가로쓰기와 위에서 아래 줄 순서를 유지한다.

## 실제 파일 검사

1. 대본의 예상 순서를 기록한 뒤, 실제 최종 이미지에서 먼저 눈에 들어오는 풍선부터 문구와 화자를 순서대로 읽는다. 대본을 알고 있다는 이유로 그림의 역순 배치를 보정해서 읽지 않는다.
2. 모든 장을 원본 크기와 약 360px 폭으로 확인한다. 질문→답변, 원인→반응, 복선→공개의 순서와 꼬리 연결을 대조한다. 같은 행의 풍선을 위아래로 읽어야 하거나 위 풍선보다 왼쪽 아래 풍선이 먼저 읽히는 배치는 실패다.
3. 애매한 경우 방향 하나로 재배치하거나 컷을 분리한다. 전체 이미지 생성은 이미지 생성 도구로 수정한다. 문자·꼬리·그림의 가림과 넘침도 다시 확인한다.
4. 검수에 파일 해시, 컷별 `dialogue_flow`, 예상 `dialogue_order`, 실제 읽힌 `observed_order`, `pass|fail`과 근거를 남긴다. 수정본은 새 해시와 모바일 미리보기로 재검수한다. 모델 시각 검수를 실제 독자 시험으로 기록하지 않는다.

순서가 뒤집히거나 두 방향이 충돌하는 장은 납품·게시 완료로 처리하지 않는다. 기존 불변 게시 패키지를 이 지침 추가만으로 수정하지 않는다.
