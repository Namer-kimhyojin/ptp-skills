# 테오·피오 웹툰 콘텐츠 모드

출연진은 [캐릭터 세트 선택](character-sets.md)으로 확정한다. 아래 테오·피오 예시는 기본 세트용이며 다른 세트에 이름·외형·역할을 강제하지 않는다. 캐릭터 없음은 컷의 `characters=[]`로 기록하고 사물·도식·내레이션으로 연결한다. 컷 구성과 가독성 검사는 그대로 적용한다. 독립 웹툰 모드 파일에도 작업의 `character_set` 스냅샷을 복사한다.

이 스킬은 `social-toon`, `four-panel`, `educational-comic`, `vertical-webtoon`, `page-comic`을 지원한다. 기관소개·설립목적·역할 설명은 [기관소개 웹툰](institution-webtoon.md)을 함께 따른다.

SNS 공고의 형식 선택, 캐릭터의 설명·실행 역할, 훅·재치·넘김 동기는 [social-storytelling.md](social-storytelling.md)를 먼저 적용한다. 만화는 캐릭터가 원인·과정·결과를 행동으로 설명하는 형식이며, 말풍선을 붙인 안내판의 반복으로 끝내지 않는다.

## 제작 범위와 검수

- 새 작업은 사용자의 전체 이미지 생성 선호에 따라 **그림·풍선·확정 대사를 통합 생성**한다. 긴 문구는 줄이거나 컷을 나눠 가독성을 확보한다. 별도 조판을 명시했거나 기존 확정 작업을 보존하는 경우에는 원화와 Paperlogy 레터링을 분리한다. 어느 방식이든 정확한 사실·문구 대조와 실제 QR 해독이 필요하다.
- 작업 범위가 확정되면 실제 정보량으로 장수·컷 수와 콘셉트를 정하고 근거를 남긴다. 추가 범위나 별도 기관 검토가 필요한 경우 해당 항목만 확인한다.
- 실제 독자·사람 검토가 없으면 없다고 기록한다. 모델의 독립 검수·자동 검사·사용자의 게시 위임을 ‘사람이 완성본을 검토함’으로 바꾸지 않는다. 기존 PTP 작업별 검수와 원격 게시 확인은 그대로 수행한다.

## 경로 선택

- 1~4컷 단발 안내: 축약 경로. 훅·설명·행동 유도를 바로 컷으로 설계한다.
- 5컷 이상, 반복 장소·의상·소품 또는 연속 회차: 표준 연속성 경로. 컷별 상태와 승인 앵커를 잠근다.
- 2화 이상: 아래 연재 기록을 작품 폴더에 유지한다. 기존 연재는 같은 작품·회차 키와 편성을 사용한다.
- 웹툰 캐러셀: `content_mode=social-toon`으로 기록하고 실제 장수와 컷 묶음을 별도 콘티에 둔다. 일반 웹툰은 정보량에 맞춰 장수와 컷을 정한다. 지원사업 길찾기 9~34화는 [연재 설명 설계](institution-webtoon.md#지원사업-길찾기-연재의-설명-설계)의 5~7장 범위를 따른다. `four-panel`은 사용자가 4컷을 요청하거나 내용상 4컷이 적합할 때 선택한다.

## 연재 기록

- 작품 폴더에 `series.json`을 둔다. `series_id`, 작품명, 독자, 작품의 정보·이야기 범위, 캐릭터 세트 스냅샷과 승인 앵커, 반복 장소·소품, 화면·레터링 규칙, `episodes[]`를 기록한다. 회차마다 번호·제목·핵심 질문·안정된 source_key·이전 회차에서 이어받는 상태·다음 회차로 넘길 상태·제작 manifest 경로를 둔다. 기존 연재에 원장이나 편성 파일이 있으면 그 자료를 사용한다.
- 회차마다 `episode-plan.json`과 아래 `panel_contract`를 사용한다. 이전 회차의 실제 마지막 컷과 콘티를 열어 인물·소품·사실의 연속성을 확인하고, 이번 회차의 변화와 다음 연결점을 기록한다. 출처와 사건을 중복 사용해야 할 때는 이유를 남긴다.
- 제작 완료 후 같은 회차 키에 실제 장 순서·장별 검수·파일 해시·채널별 게시 결과를 연결한다. 제작·게시 상태는 기존 [공통 장부](social-publishing.md#중복-방지와-실행-이력)에서 확인한다.

## 필수 제작 계약

모든 대화는 [대사 읽기 순서](dialogue-reading-order.md)를 읽고 컷별 `dialogue_flow=left-to-right|top-to-bottom`, 발화 순서·화자·문구를 `dialogue_order`에 기록한다. 한 대화 묶음에서 두 방향이 충돌하는 배치는 허용하지 않는다. 재미 목적의 단편은 [PTP 반짝 웹툰](spark-webtoon.md)의 반전·출처 배치와 개그 리듬을 우선하며 아래 정보 안내용 흐름·CTA를 강제하지 않는다.

- `content_mode`: `social-toon|four-panel|educational-comic|vertical-webtoon|page-comic`
- `reading_direction`: 기본 `left-to-right`, 세로 스크롤은 `vertical-scroll`
- `panel_count`: 실제 패널 수와 일치하는 양의 정수
- `frame_diversity`: `uniform|controlled|expressive`
- `story_beats`: `hook → context/problem → explanation/action → CTA/resolution`
- `panel_contract[]`: 컷 번호, 기능, 화면 행동, 핵심 정보, 출처, 등장 캐릭터, 레터링 안전영역

`assets/webtoon-mode-template.json`의 4컷은 작성 예시다. 선택한 형식의 실제 컷 수에 맞게 `panel_count`, `panel_contract`, `story_beats`를 조정한다. 콘티에는 독자의 질문, 장/컷별 답, 화자, 대사, 표정, 다음 장을 읽을 이유도 남긴다.

한 컷의 핵심 정보는 하나를 기본으로 한다. 대사와 캡션은 짧고 자연스럽게 쓰며 그림이 이미 보여주는 내용을 반복 설명하지 않는다. 기관 정책·수치·절차는 컷별 출처와 연결한다.

## 통합 생성과 별도 조판

[컷별 장면 변화](creative-variation.md#웹툰의-컷별-장면-변화)에 따라 원화 재활용을 최소화한다. 같은 상담실·인물이어도 몸·손·표정·시선·카메라·구도가 사건에 맞게 변해야 한다. 완성 장면의 말풍선만 교체하는 제작은 하지 않는다. 연속 컷은 나란히 비교해 실제 시각적 진전을 확인한다.

- 통합 생성은 장면·말풍선·확정 한글·기관 표기·출처를 함께 명세한다. 반복 캐릭터는 매 장마다 승인 앵커와 앞 장을 참조하고 전체 연속성을 검수한다.
- 별도 조판 모드에서만 무문자 원화와 프레임·거터·Paperlogy 레터링을 분리한다.
- 게시용 한 장은 하나의 명확한 장면 또는 읽기 쉬운 컷 묶음으로 생성한다. 여러 장을 한 이미지로 생성한 뒤 임의 분할해 납품하지 않는다.
- SNS 변환은 단순 리사이즈하지 않고 컷 묶음, 거터, 크롭, 말풍선과 캡션을 다시 흐르게 한다.

## 캐릭터 연속성

테오·피오의 모든 등장 컷은 승인된 v1.2 앵커와 `default` 복장을 사용한다. 각 컷에서 얼굴, 2.7등신 체형, 둥근 몸통, 팔다리 굵기, 피오의 흰색 일체형 기본복과 주황 측면 패널, 화면 기준 오른쪽 가슴 상단의 작은 `T/P`, 머리 무표식을 확인한다. 다른 출연진에는 선택한 세트·오리지널 인물의 실제 앵커를 적용하며 테오·피오의 체형·가슴 문자를 요구하지 않는다.

연속 컷에는 `state_before`와 `state_after`를 두어 손에 든 물건, 위치, 시선, 조명, 의상 상태가 이유 없이 바뀌지 않게 한다. 말하는 캐릭터와 말풍선 꼬리, 대화축과 좌우 위치도 검수한다.

## 형식별 연출

- `social-toon`: 훅 → 맥락 → 설명·실행 → CTA의 정보 흐름을 필요한 컷과 장에 배분한다. 컷 수보다 독자의 이해 변화가 기준이다.
- `four-panel`: 1컷 훅, 2컷 맥락, 3컷 해결·절차, 4컷 CTA에서 시작하되 소재에 맞게 리듬을 조정한다.
- `educational-comic`: 질문, 오해 또는 문제를 먼저 보여주고 테오가 원리·정책을, 피오가 실행 방법을 설명한다.
- `vertical-webtoon`: 기준 모바일 뷰포트별 정보·정지·공개를 설계한다. 긴 거터는 시간·거리·침묵의 의미가 있을 때만 쓴다.
- `page-comic`: 페이지 내 시선 이동과 프레임 위계를 먼저 잠그고 재단·안전영역을 확인한다.

웹툰도 `assets/visual-concept-presets.json`에서 서로 다른 3개 시각 콘셉트를 제안할 수 있다. 실사·시네마틱 배경을 쓸 때는 컷마다 광원·원근·그림자·깊이와 캐릭터 색을 연속적으로 유지한다.

비교 제안은 요청되었거나 선택에 실질적 도움이 있을 때 사용한다. 이미 제작을 위임받았다면 콘셉트 선택과 근거를 기록하고 진행하며, 별도의 3안 승인 단계를 강제하지 않는다. 마지막 CTA는 정확한 접수 경로와 원문 확인으로 연결한다.

## 품질 확인

말풍선의 글자 넘침은 [이름표·대사·실제 높이 검사](lettering-safety.md)로 차단한다. 두 줄 대사를 한 줄 기준의 고정 박스에 넣지 않는다. 새로운 편의 서사와 레이아웃은 [최근 제작물 비교](creative-variation.md)를 거쳐 선택하고 한 편 안에서도 장별 이해 변화에 맞춰 컷·카메라·말풍선 위치를 바꾼다.

- 첫 독해에서 컷 순서, 화자, 핵심 정보, 다음 행동이 명확한가
- 한 대화 묶음이 왼쪽→오른쪽 또는 위→아래로만 읽히며, 실제 풍선 순서가 대본의 발화 순서와 일치하는가. 질문보다 답변이 먼저 읽히면 실패로 수정한다.
- 같은 인물이 컷마다 얼굴·체형·복장·가슴 문자가 유지되는가
- 같은 샷과 표정만 반복하지 않고 정보와 감정에 맞게 거리가 바뀌는가
- 말풍선 안전영역이 얼굴·손동작·핵심 수치와 충돌하지 않는가
- 테오는 이해를, 피오는 실행을 진전시키며 둘의 행동이 해당 정보를 전달하는가
- 비유·재치·결말이 사실을 바꾸거나 지원 대상·담당자를 낮추지 않는가
- 약 360px 폭 미리보기에서 대사·필수 조건을 확대 없이 읽고, 캐러셀 각 장의 순서를 이해할 수 있는가
- 사실·권리·기관 브랜드·생성 도구 상업 약관·AI 공개 정책이 확인됐는가
