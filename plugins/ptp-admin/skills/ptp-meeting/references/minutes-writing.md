# 회의록 작성 규칙

## 출력 구조

회의 결과 영역은 아래 위계를 유지한다. 채팅으로 회의 결과 텍스트를 제공할 때는 복사할 수 있는 마크다운 코드블록으로 제공한다. HWPX 파일 안에는 마크다운 볼드나 코드펜스를 넣지 않는다.

```text
❑ 회의 결과
 ◦ 안건 제목
 - 논의 사항 요약
   필요시 추가 내용
```

- `❑ 회의 결과`는 최상위 시작 문구이며 굵게 쓰지 않는다.
- `◦` 안건은 일반 요청 3~4개, `간략히` 요청은 정확히 3개다.
- 각 안건의 `-` 항목은 2~4개로 한다. 근거가 부족하면 개수를 채우지 말고 확인을 요청한다.
- 각 `-` 문장은 공백과 기호를 제외하고 18~25자를 목표로 한다.
- 안건 제목은 굵게 쓰지 않는다.
- 회의비·예산과목·단순 행정처리는 결과 본문에서 제외한다.
- 연도는 필요하면 `'25년`처럼 줄이고, 전체 사업명은 문맥상 안전할 때 `아카데미사업`으로 줄인다.

## 내용 선택

1. 먼저 실제 회의 메모, 발언 요지, 결과 자료가 있는지 묻는다. 있으면 그 내용을 근거로 작성한다.
2. 자료가 없고 사용자가 초안을 원하면 기안문의 회의명·목적·논의 예정 사항 범위 안에서만 **초안**을 만든다. 이때 결과 보고에 "기안문 기반 초안이며 실제 논의 확인 필요"라고 알린다.
3. 확인되지 않은 결정·합의·성과·일정은 쓰지 않는다. `추진하기로 함`은 자료에 명시된 합의에만 쓴다.
4. 숫자·금액·정확한 날짜는 기안문이나 영수증에 있는 경우에만 해당 필드에 쓴다.

`~함`, `~됨`을 반복하지 말고 `검토`, `추진`, `보고`, `요청`, `확인`, `논의` 등 근거에 맞는 표현을 쓴다.

## 참석자 표기

- 내부·외부 구분은 실제 문단 또는 명시적 줄바꿈으로 나눈다.
- 내부 그룹에는 `포항테크노파크`, `포항TP`, `(재)포항테크노파크` 같은 기관명을 쓰지 않고 직위·성명만 쓴다.
- 내부 명단이 길면 쉼표 뒤에서 다음 줄로 넘기고, 다음 줄 시작 위치를 맞춘다.
- 외부 그룹은 기관별로 한 줄씩 두고 기관명과 직위·성명을 함께 쓴다. 여러 기관을 `/`로 이어 압축하지 않는다.
- HWPX XML에서 문단을 복제할 때는 `hp:p/@id`를 고유하게 다시 부여하고 `hp:linesegarray` 캐시를 제거한다.
- 렌더링할 수 있으면 글자 겹침·잘림·넘침을 확인한다. 공간이 부족하면 참석자 영역 안에서만 글자 크기와 문단 간격을 조정한다.

```text
◦ 내부 (4명) : 김○○ 팀장, 이○○ 대리,
               박○○ 사원, 최○○ 사원
◦ 외부 (3명)
 - A협회 : 홍○○ 이사, 정○○ 팀장
 - B대학교 : 윤○○ 교수
```
