# 테오·피오 SNS 스토리텔링

출연진은 [character-sets.md](character-sets.md)의 선택 결과를 우선한다. 아래 테오·피오는 기본 세트 예시다. 다른 세트에는 고유 역할과 이름을 사용하고, 캐릭터 없음에는 주제 장면·사물·정보 위계·내레이션으로 훅과 이해 변화를 만든다.

[단일 이미지/카드뉴스 선택](single-image-social.md)을 먼저 적용한다. 단일 홍보 이미지를 골랐으면 아래의 여러 장·대화·넘김 연출을 강제하지 않고, 한 장의 핵심 요약·콘셉트 장면·CTA로 압축한다.

목표는 캐릭터를 많이 넣는 것이 아니라, 테오·피오의 질문·판단·행동 덕분에 독자가 공고를 이해하고 다음 행동을 할 수 있게 만드는 것이다. 사업공고 카드뉴스와 SNS 만화는 이 기준을 기본 적용한다. [캐릭터 정체성](character-identity.md), [시각 콘셉트](visual-concept-system.md), [웹툰 제작](webtoon-content-mode.md)의 잠금은 그대로 유지한다.

## 1. 사실에서 형식 선택

먼저 `독자 / 독자가 겪는 망설임 / 읽은 뒤 알게 될 것 / 다음 행동 / 원문 근거`를 한 줄씩 정한다. 사실 목록을 그대로 카드 수로 바꾸지 않는다.

| 형식 | 선택 신호 | 테오·피오의 기능 |
|---|---|---|
| 정보형 `information` | 마감·대상·신청 경로처럼 빠른 판단이 우선 | 테오가 조건의 관계를 보여주고 피오가 체크·선택·신청의 동작을 수행 |
| 대화형 `dialogue` | 용어, 지원 방식, 절차를 질문과 답으로 풀면 쉬워짐 | 테오가 왜·어떻게를 설명하고 피오가 현실적인 실행 질문과 다음 단계를 연결 |
| 스토리형 `story` | 문제 발견 → 확인 → 실행으로 변화하는 장면이 이해에 도움 | 두 캐릭터가 작은 과제를 해결하는 SNS 웹툰·웹툰 캐러셀 |

- 사용자가 형식을 지정하면 따른다. 위임된 제작은 가장 적합한 형식을 선택하고 이유를 제작 기록에 한 문장 남긴다. 캐릭터 설명·만화를 요청받은 경우 대화형 또는 스토리형을 우선 검토한다.
- 대화·이야기 뒤에 대상·마감·방법을 정리하는 정보 카드를 섞어도 된다. 장수·컷 수는 정보량과 모바일 독해로 결정한다. 5장 또는 4컷을 기본 할당량으로 강제하지 않는다.
- 한눈에 끝날 내용을 억지로 연재하거나, 필수 조건을 숨겨 다음 장을 넘기게 하지 않는다. 접수 여부를 좌우하는 조건은 관련 혜택과 같은 장 또는 바로 이어지는 설명에 둔다.
- 사용자가 비교를 요청한 경우 시안을 제시한다. 이미 제작을 맡겼으면 짧은 내부 아이디어 비교 후 한 안으로 진행하며, 콘셉트 3안 승인 단계를 새로 만들지 않는다.

## 2. 역할은 유지하고 행동은 다양하게

- **테오: 이해를 만드는 안내자.** 복잡한 관계를 분해하고, 조건을 비교하고, 순서를 드러낸다. 손가락으로 제목만 가리키는 동작보다 길을 연결하거나 조건 패널을 정렬하는 행동을 쓴다.
- **피오: 실행을 만드는 동반자.** 독자에게 필요한 질문을 던지고, 체크리스트를 적용하고, 서류·절차를 준비한다. 늘 모르는 역할이나 실수하는 역할로 고정하지 않는다.
- 둘의 대화는 `테오의 설명 → 피오의 실행 → 새로 확인할 조건`처럼 원인·과정·결과를 연결한다. 같은 내용을 두 번 말하거나 두 캐릭터가 같은 손짓을 반복하지 않는다.
- 캐릭터의 시선, 손, 소품, 위치 변화 중 하나 이상이 해당 정보와 연결되어야 한다. 독자가 보아야 할 곳으로 시선이 이어지게 하고, 핵심 숫자·조건·마감과 겹치지 않게 한다.
- 캐릭터는 선정 권한자·심사위원·실제 수혜기업을 연기하지 않는다. 신청 장면의 결말은 `준비 완료`, `원문 확인`, `신청 단계 이해`로 잡는다. 선정·매출 상승·정부사업 통과를 보장하는 결말은 금지한다.
- 몸·머리·기본복·가슴 문자 잠금을 지킨다. 활약을 늘리기 위해 새 의상·로고·머리 장식을 만들지 않는다. 소품은 설명에 필요한 것만 사용한다.

## 3. 첫 장의 훅과 넘길 이유

첫 장은 독자의 실제 질문 하나를 잡고, 이 게시물에서 얻을 답을 약속한다. `공감 → 궁금증 → 확인 → 실행`의 리듬을 소재에 맞게 조절한다.

| 아이디어 출발점 | 장면과 정보의 결합 | 다음 장의 보상 |
|---|---|---|
| “지원금 숫자보다 먼저 볼 한 줄” | 테오가 자격 조건을 찾아 펼치고 피오가 자기 점검표에 연결 | 누가 신청할 수 있는지 바로 확인 |
| “이 지원, 어떻게 받는 걸까?” | 두 캐릭터가 신청자·수행기관·지원기관 사이의 실제 흐름을 잇기 | 지원 방식과 신청자가 할 일 이해 |
| “공고 속 길찾기” | 테오는 조건을 표지판으로, 피오는 실제 절차를 이동 경로로 표현 | 단계와 준비사항을 순서대로 파악 |
| “질문 하나, 준비 한 칸” | 짧은 질문을 해결할 때마다 피오의 준비 항목이 채워짐 | 마지막에 독자도 쓸 수 있는 체크리스트 |

위 문구는 아이디어 예시다. 모든 공고에 반복하거나 원문에 없는 조건·단계를 만들어 맞추지 않는다. 숫자형 훅의 숫자는 실제 항목 수와 일치해야 한다.

- 재치는 상황의 발견, 소품의 쓰임, 짧은 대화의 호흡, 앞 장에서 던진 질문의 회수로 만든다. 지원 대상·기업 규모·지역·담당자의 무지를 웃음거리로 쓰지 않는다.
- 과장된 혜택, 가짜 긴급성, 선정 확정 암시, “무조건”, “돈 받자”, “놓치면 손해”식 압박을 쓰지 않는다. 사실과 다른 오해 문장을 표지에 크게 제시한 뒤 뒷장에서만 정정하지 않는다.
- 유행어·밈은 독자가 이해하고 공공기관 어조에 맞는 경우에만 짧게 쓴다. 특정 작품·유명 캐릭터·저작물의 장면을 그대로 모방하지 않는다.
- 넘김 유도는 다음에 해결할 질문을 자연스럽게 남기는 방식으로 한다. 의미 없는 “다음 장 필수”, 좋아요·태그 강요, 반복 CTA로 채우지 않는다.

## 4. 제작 계약

콘티 또는 `card-plan.json`에 다음을 남긴다. 기존 job 스키마에 지원되지 않는 필드를 억지로 추가하지 않고 별도 기획 파일로 관리할 수 있다.

- 전체: `narrative_mode`, 대상 독자, 독자의 질문, 선택한 아이디어와 이유, 최종 행동, 실제 장수·컷 수
- 장/컷별: 목적, 독자가 얻을 답, 사실 문장과 출처, 테오·피오의 행동·표정·화자, 대사·캡션, 시선 이동, 레터링 안전영역
- 스토리형: 이전·이후 상태, 컷 전환 이유, 소품·위치·대화축의 연속성
- 마지막 CTA: 정확한 마감일·시간, 신청 경로, 문의, 원문 링크. QR 사용 시 별도 QR 기준에 따라 원문 확인 동작과 연결하되 휴대전화에서 바로 이용할 문자 경로도 제공

새 작업은 그림·말풍선·확정 대사·정보·출처·CTA를 함께 생성한다. 한글·날짜·금액은 결과와 원문을 글자 단위로 대조하고, QR은 실제 URL로 생성한 참조를 사용해 최종 이미지에서 해독한다. 별도 조판을 명시하거나 기존 확정 작업을 보존하는 경우에만 원화·풍선·Paperlogy 문자 레이어를 분리한다.

## 5. SNS에서 읽히게 조립

- 피드의 첫 화면은 작은 미리보기에서도 주제와 대상이 드러나게 한다. 첫 장 안에 모든 공고 항목을 몰아넣지 않는다.
- 캐러셀 한 장은 한 번의 이해 또는 한 번의 행동 변화를 담당한다. 웹툰 캐러셀은 보통 한 장 1~2컷에서 시작하되 실제 가독성에 따라 조절한다.
- 말풍선은 한 개에 한 문장, 한 컷 1~2개에서 시작한다. 짧은 대사로 줄이고 필요한 조건은 명료한 정보 패널로 분리한다. 대사와 캡션이 같은 내용을 반복하지 않게 한다.
- 1080px 폭 원본을 약 360px 폭으로 보며 본문·대사·필수 조건을 확대 없이 읽을 수 있는지 확인한다. 핵심 대사는 대략 39~48px부터 검토하고, 실제 서체와 줄 수로 조절한다. 공간이 부족하면 컷·장을 나누며 글자를 계속 줄이지 않는다.
- Instagram은 넘김 순서와 첫 줄 훅, 저장해 다시 볼 정보, 마지막 행동을 연결한다. 피드 캡션 URL이 항상 클릭된다고 전제하지 않고, 실제 설정을 확인하지 않은 “프로필 링크” 안내를 쓰지 않는다.
- Facebook은 단일 이미지·사진 묶음의 노출 순서나 크롭이 달라도 제목·첫 캡션에서 대상과 목적을 이해할 수 있게 한다. 원문 링크와 신청 핵심을 캡션에도 제공하고 실제 게시 미리보기로 확인한다.
- 대체텍스트에는 장면의 역할, 화자, 핵심 대사·조건을 읽는 순서대로 담는다. 외모 묘사만으로 중요한 안내를 대체하지 않는다.

## 6. 게시 전 이야기 검사

1. 첫 화면만 보고 누구에게 무엇을 알려 주는지 알 수 있는가?
2. 각 장·컷에서 캐릭터의 행동이 어떤 정보를 전달하는지 한 문장으로 설명할 수 있는가? 설명할 수 없다면 동작·장면을 바꾸거나 그 컷을 줄인다.
3. 캐릭터를 지우면 설명의 이해나 다음 행동의 연결이 약해지는가? 변화가 없다면 장식 배치를 기능적 장면으로 수정한다.
4. 그림의 비유를 실제 지원 조건·지급 방식·선정 결과로 오해할 여지가 없는가?
5. 대사를 빼도 동작의 목적이 보이고, 그림을 못 보아도 대체텍스트로 핵심 사실을 알 수 있는가?
6. 대상·금액·기간·마감 시각·지급 방식·절차가 출처와 일치하는가? 농담이나 요약 때문에 제한 조건이 사라지지 않았는가?
7. 작은 화면에서 컷 순서·화자·말풍선 꼬리·필수 정보·최종 행동을 읽을 수 있는가?

검수 결과는 실제 읽기·렌더 확인 근거와 함께 기록한다. 자동 검사나 모델 검토를 실제 독자의 반응·재미·성과로 주장하지 않는다.
