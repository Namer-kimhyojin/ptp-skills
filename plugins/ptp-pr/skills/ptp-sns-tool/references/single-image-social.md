# 형식 선택과 단일 홍보 이미지

단순 사업 안내·행사 홍보·홈페이지 게시 자료의 핵심 요약은 **단일 홍보 이미지 1장**으로 제작·게시할 수 있다. 카드뉴스도 계속 지원한다. 첨부 참고 이미지는 시각 구성 참고이며, 그 안의 행사명·날짜·가격·장소·혜택을 현재 PTP 사실로 복사하지 않는다.

## 실행할 때 한 번 묻고 10초 대기

새 SNS 콘텐츠의 형식이 명시되지 않은 실행에서 사용 가능한 비동기 질문 도구로 다음 한 가지를 묻는다. 스킬 수정·검사 요청은 새 콘텐츠 실행이 아니므로 질문·제작·게시를 시작하지 않는다. `단일 이미지로`, `카드뉴스로`, `웹툰 캐러셀로`처럼 이미 지정했다면 그 값을 적용하며 되묻지 않는다.

> 이번 콘텐츠를 어떤 형식으로 제작할까요? ① 단일 홍보 이미지 1장 ② 카드뉴스 여러 장. 10초 동안 응답이 없으면 단일 이미지로 진행합니다.

1. `request_user_input_async` 등 대화를 막지 않는 질문 도구를 사용한다. 선택지는 `단일 홍보 이미지 1장 (기본)`과 `카드뉴스 여러 장`이다. UI에서 기본값이 미리 선택된 것을 사용자 응답으로 기록하지 않는다.
2. 질문이 실제 표시된 시각을 시간대가 있는 `asked_at`으로 기록한다. 만료는 이 시각부터 **10초**다. 질문 중에는 원문 수집·기존 이력 조회 등 형식과 무관한 작업을 할 수 있다. 단일/다중 장 원화 생성은 선택 확정 후 시작한다.
3. 유효한 응답을 받으면 즉시 해당 형식을 선택한다. 응답이 없고 10초가 지나지 않았다면 남은 시간만 대기한다. 현재 대화에 입력이 오면 일찍 끝나는 `clock.sleep` 같은 대기 도구를 사용하고, 입력이 오면 그 의미를 먼저 반영한다. 10초가 지나면 `single-image`로 결정하고 “10초 동안 형식 응답이 없어 단일 이미지로 진행합니다”라고 알린다. 다시 질문하거나 추가 답변을 기다리며 턴을 끝내지 않는다.
4. `scripts/resolve_delivery_form.py`로 질문 시각·현재 시각·실제 응답 수신 시각을 검사할 수 있다. 이 도구는 채팅 질문·응답 수신·백그라운드 타이머 자체를 실행하지 않는다. 에이전트가 실행 중일 때 지원되는 질문·대기 도구와 함께 사용한다. 만료 후 늦게 관찰된 응답이라도 실제 수신이 만료 전이면 사용자 선택이 우선이다.
5. 결과를 `job.format_selection`에, 확정값을 `job.delivery_form`에 저장한다. `single-image` 또는 `card-news`다. 늦은 변경 요청은 현재 진행 단계를 확인해 반영한다. 이미 공개된 글을 형식 응답만으로 자동 삭제·재게시하지 않는다. 취소·중단·다른 명시적 지시는 타이머보다 우선한다.

실시간 질문 도구가 없으면 단일 이미지 기본값을 안내하고, 아직 필요한 캐릭터·게시 범위 질문에 카드뉴스 선택도 함께 적는다. 이 경우 10초 타이머를 실행했다고 기록하지 않는다.

```powershell
python scripts/resolve_delivery_form.py --asked-at <실제질문시각ISO> --now <현재시각ISO>
python scripts/resolve_delivery_form.py --asked-at <실제질문시각ISO> --now <현재시각ISO> --response card-news --received-at <실제응답수신시각ISO>
python scripts/resolve_context.py --workflow notice-to-social --delivery-form single-image --production-mode publication --platform instagram --format png
```

10초 기본값은 형식에 적용한다. [게시 기본값](default-publication.md)에서 게시 범위가 확정된 작업은 선택 형식으로 검수하고 공개한다. 형식이 바뀌어도 공고·계정별 중복 키와 기존 게시 상태를 사용한다.

## 한 장에 적합한 구성

- `assets/single-image-job-template.json`에서 시작한다. `delivery_form=single-image`, `output.mode=social-post`, 각 `platform_targets[].content_type=social-post`, `target_count=1`, PNG 수량 1, `copy.cards` 1개다. 여러 채널에 같은 이미지가 쓰여도 각 게시물의 사진 수는 1장이다. 복수 장 웹툰의 `comic` 계약을 그대로 물려받지 않는다.
- 단일 이미지 피드는 Instagram·Facebook 모두 **1080×1080(1:1)** 공용 PNG 한 장으로 제작한다. 스토리·캐러셀 등은 해당 지면 프리셋을 사용한다.
- 정사각형 캔버스에 배경을 끝까지 채우고 제목·캐릭터·로고·QR을 재배치한다. 빈 띠나 강제 늘이기를 피한다. 최종 픽셀, 360×360 미리보기, QR 해독과 양쪽 피드 미리보기를 검수한다.
- 새 단일 이미지 job에 `channel_image_policy=shared-square-feed`를 기록한다. 검수 spec에 `expected_size=[1080,1080]`과 공용 파일 한 장을 기록하고 job·manifest에 연결한다. 각 채널에 같은 PNG 한 장을 올리며 채널별 문안과 게시 이력을 확인한다.
- 이미지에 `무엇을 안내하는가`, `누구에게 어떤 기회인가`, `언제·어디서 또는 언제까지`, `어떻게 신청·확인하는가`가 보이게 한다. 한 개의 강한 제목, 핵심 혜택/메시지, 꼭 필요한 일정·대상·장소·신청, CTA·문의·출처·QR을 위계에 맞게 정리한다. 관련 없는 항목을 채우기 위해 사실을 만들지 않는다.
- 사업은 대상·혜택·정확한 접수 마감·신청 경로를, 행사는 주요 내용·일시·장소·신청 정보를 우선한다. 중요한 자격 제한·비용·민간부담·변경 조건은 오해가 없게 요약하고 전체 내용은 캡션·공고문에 연결한다. 꼭 필요한 조건조차 읽히게 넣을 수 없으면 원문과 연결하는 더 짧은 문구로 정리하고 배치를 다시 설계한다. 무응답 기본값을 이유로 임의로 여러 장을 만들지 않는다.
- 긴 프로그램·모든 예외·제출서류 전체를 한 장에 축소하지 않는다. 이 사용자의 기본값은 `generation_method=whole-image`: 확정 한글·장면·서체 분위기·광원·정보 위계·검증된 실제 QR 참조를 함께 주고 완성 포스터를 한 번에 생성한다. 별도 문자 합성을 요구하지 않는다. 생성한 한글은 확정 문구와 전체 대조하고 [생성 문자 검수](lettering-safety.md)와 약 360px 폭 시각 검수를 적용한다. QR은 참조를 주었다는 이유만으로 성공으로 기록하지 않고 최종 이미지에서 실제 URL 해독을 확인한다. 실패 시 이미지 생성 도구로 정확한 QR 참조와 함께 수정·재생성한다. 별도 조판은 사용자가 선택한 경우에 적용한다.
- 테오·피오는 콘셉트와 CTA를 돕는 설명·관찰·실행 동작으로 참여한다. 단일 이미지에는 두 말풍선이나 만화 프레임을 강제하지 않는다. 실사 합성·편집형·3D·포스터형 등 [최근 제작물과 다른 구성](creative-variation.md)을 선택한다.

## 납품·게시

### 상업 홍보 포스터의 시선 흐름

단일 이미지는 안내문을 정리한 화면으로 끝내지 않는다. 모집명/행사 주제 → 가장 중요한 혜택/메시지 → 참여조건 → 신청 행동의 순서를 먼저 설계하고, 제목·핵심 수치·보조 정보 사이에 분명한 크기 차이를 둔다. 사진을 가로 띠에만 가두거나 상단 색면과 하단 목록으로 매번 나누지 않는다. 내용에 맞는 현장·소재를 지면 전체의 빛·원근·여백과 연결하고 정보가 놓일 공간부터 확보한다. 큰 수치에는 1인당/기업당·최대·제외조건을 함께 둔다. 박스·구분선·아이콘은 실제 읽기를 도울 때만 사용한다.

검수에서는 약 360px 폭에서 3초 안에 주제와 핵심 혜택이 먼저 보이는지 확인하고, 대상과 CTA까지 시선이 이어지는지 본다. 사실 정확성·여백 검사 통과를 디자인 완성도로 대신하지 않는다. 이 기준은 고정 템플릿이 아니며 실사·타이포·오브젝트·에디토리얼 등 구성은 매회 달라질 수 있다.

사용자의 명시적 품질 수정은 원본 패키지를 보존한 별도 개선본으로 제작한다. `content_history.py revise-creative`는 직전 제작 이벤트·원본 해시·별도 manifest·실제 사용자 수정 요청을 연결한다. `submitting/unknown/scheduled` 채널이 있으면 먼저 원래 시도를 해결한다. 이미 게시된 채널의 중복 차단은 그대로 유지하며, 개선본 등록 자체가 삭제·재게시 승인이 되지 않는다. 사진 교체를 지원하지 않는 채널에서는 완성 개선본을 제시한 후 기존 게시물 처리에 대한 사용자 결정을 받는다.

채널별 최종 PNG 1장과 해당 대체텍스트, Instagram·Facebook 각각의 캡션, source/facts/job, 실제 수행한 문자 검수와 최종 QR 해독 보고서, 패키지 manifest를 보관한다. 전체 이미지 생성은 프롬프트·원본 생성 PNG·문구 대조 근거를 보존하며 무문자 원화나 문자 실측 보고서가 있는 것처럼 기록하지 않는다. 별도 조판은 무문자 원화와 문자 측정 보고서도 보관한다. 미리보기는 업로드용 사진 수에 더하지 않는다. 채널에 올리는 파일 목록이 정확히 1개인지 검증한다.

카드뉴스를 골랐으면 `delivery_form=card-news`와 실제 다중 장 수량을 기록해 기존 설명·웹툰 절차로 진행한다. 단일·다중 어느 형식이든 같은 제작·게시 장부, 공고 접수기간·정정·취소 검사, 최종 검수, 저장 로그인, 채널별 제출/성공/불명 상태와 실제 공개 확인을 사용한다. 단일 이미지를 지원한다는 이유로 기존에 게시한 공고를 다시 게시하지 않는다. 기존 SNS 글을 새 이미지로 재요약해 재게시하는 요청이면 해당 기존 글과 사용자 변경 범위를 먼저 확인한다.
