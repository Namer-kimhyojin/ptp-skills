# 매회 다른 콘셉트와 구성

새 publication 패키지는 [파일에 연결된 검수](content-review.md)에 실제 완성본과 이전 디자인 비교 근거를 연결한다. 자동 추천이나 signature 문자열만으로 차별성이 검증된 것으로 기록하지 않는다.

새 공고는 최근 완성본과 비교해 독자의 보는 경험을 바꾼다. 승인 캐릭터·정보 정확성·기관 식별은 유지하면서 **서사 형식과 지면 구성**을 함께 변화시킨다. 색·배경·소품만 바꾼 동일 템플릿은 변화로 세지 않는다. 사용자가 특정 시리즈 형식을 고정했으면 그 선택을 우선하고 반복 근거를 기록한다.

## 이전 결과를 읽고 선택하기

```powershell
python scripts/resolve_concept.py --signal announcement --signal eligibility --signal deadline --tone friendly --photo none --source-key ptp:15:<새공고ID> --out <concept-selection.json>
```

- 기본 공유 제작 장부의 최근 **6개 공고**를 읽는다. 같은 공고의 채널·수정 패키지를 여러 편으로 세지 않는다. `--lookback`으로 범위를 바꿀 수 있다. 별도 빈 장부로 이전 디자인 비교를 우회하지 않는다.
- `recent_designs`의 실제 `preview_path`를 열어 표지·중간 장·CTA를 비교한다. 최근 콘셉트와 같은 매체군에는 반복 감점이 적용된다. `presentation_proposals`는 서사 형식과 레이아웃의 최근 반복을 별도로 감점한다.
- 자료에 맞는 매체 3안과 서사·구성 후보를 비교해 선택한다. 자동 추천은 기획 보조이며 최종 이미지의 차별성을 증명하지 않는다. 위임받은 선택을 승인 질문으로 바꾸지 않는다.
- 이력이 없으면 첫 제작이라고 기록한다. 장부 오류는 보존하고 확인한다. 이전 파일이 사라졌거나 구성 기록이 비었으면 `history_warnings`를 남기며 과거와 다름이 검증됐다고 단정하지 않는다. 원문 전달에 부적합한 형식을 무작위로 고르지 않는다.

## 바꿔야 할 독자 경험

직전 자동 선택 형식과 같은 서사·레이아웃 조합을 연속 사용하지 않는다. 의도적인 후속 편이거나 사용자가 고정했다면 이유를 기록한다. 그 외에는 앞의 두 축을 함께 바꾸고 나머지는 내용에 맞게 선택한다.

| 변화 축 | 예시 |
|---|---|
| 서사·읽기 방식 | 미션 해결, 질문–답 공개, 인터뷰, 뉴스룸, 전후 비교, 현장 탐방, 신청 길찾기 |
| 지면·컷 구성 | 큰 장면에 대사 배치, 크기가 다른 여러 컷, 잡지 편집, 좌우 비교, 경로형, 큰 인용문과 관찰 메모 |
| 매체·재질 | 실사 합성, 3D 공간, 페이퍼 콜라주, 일러스트·편집 혼합 |
| 훅·정서 | 기업의 실제 질문, 마감 긴장, 오해 발견, 발견과 반전, 준비의 성취감 |
| 캐릭터 행동·카메라 | 탐색·관찰·비교·실험·인터뷰·선택·협업, 전체 장면과 손·표정·소품의 확대 교차 |

`assets/creative-formats.json`은 출발점이다. 카탈로그 밖의 더 적합한 아이디어도 쓸 수 있으며 항목 순서대로 고정 순환하지 않는다. 캐릭터의 복장·체형·머리·가슴 표식을 변경해 차이를 만들지 않는다. 재치는 공고의 사실·필수 조건을 바꾸거나 독자를 낮추지 않아야 한다.

한 편 안에서도 모든 장을 `제목 → 같은 크기 말풍선 2개 → 큰 그림 → 하단 흰 정보박스`로 복제하지 않는다. 색·서체·읽기 규칙을 일관되게 유지하면서 질문, 설명, 행동, 비교, 신청 등 장별 기능에 맞춰 장면·컷 수·말풍선 위치·정보 비중을 바꾼다. 장마다 무작위 디자인으로 바꾸는 것도 피한다. 장수는 실제 정보량으로 정한다.

## 웹툰의 컷별 장면 변화

완성 컷·장면을 복제한 뒤 말풍선만 바꿔 새 컷으로 만들지 않는다. 같은 자세·얼굴·손·책상·배경을 유지한 채 입 모양이나 대사만 바뀌는 장면도 반복으로 본다. 좌우 반전, 약간의 크롭·확대, 색·소품 변경만으로 새 연출을 만들었다고 기록하지 않는다. 웹툰 원화의 재활용은 가급적 피하고 컷의 사건에 맞춰 새로 그린다.

승인 마스터 시트, 캐릭터 외형·복장·장소 설정을 **정체성 참조**로 사용하는 것은 유지한다. 같은 장소라도 카메라 높이·거리·시점, 인물의 몸·손·시선·자세, 상대와의 거리, 전경·배경의 비중을 해당 순간에 맞게 새로 구성한다. 변화 자체를 위한 무작위 화면 전환이나 캐릭터 외형 변경은 피한다.

콘티에 컷별 `visual_change_from_previous`와 `dramatic_purpose`를 기록한다. 예: “두 인물의 전체 샷 → 질문자의 기대에 찬 얼굴 → 답변자의 가방을 쥔 손과 무표정 → 상상 장면의 과잉 확대 → 놀라서 뒤로 물러나는 반응”. 단순히 카메라 이름을 다르게 적는 것만으로 통과시키지 않는다. 그림에서 보이는 행동·정보·감정의 변화가 정적·오해 확대·반전의 리듬을 만들어야 한다.

**각 장이 극적인 장면으로 읽혀야 한다.** 장마다 중심 사건과 감정의 변화를 정하고, 그 장의 가장 강한 시각적 순간(`page_peak`)을 설계한다. 원근·크기 대비·행동·명암·여백 중 소재에 맞는 수단으로 기대·긴장·반전·정적을 느끼게 한다. 매 컷을 소리치게 하거나 효과선만 늘리는 것을 극적 연출로 보지 않는다. 작은 물건을 지나치게 거창하게 보여주거나, 과열된 장면 뒤 넓은 공백과 멈춘 몸짓으로 정적을 만드는 것도 사용할 수 있다.

인접 컷은 **구도·표정·몸짓**을 직접 대조한다. 같은 찡그린 얼굴과 물건을 든 자세를 유지한 채 가까이 확대하는 것도 이번 사용자가 지적한 반복이다. 컷을 새로 생성했더라도 실질적으로 같은 연기와 구도면 실패다. 복장·얼굴 정체성을 유지하면서 눈·눈썹·입·목·어깨·손과 체중 이동으로 감정을 진전시키고, 거리에 맞는 카메라와 전경·배경을 새로 그린다. 무표정 개그도 동일 초상을 반복하지 말고 주변 인물의 변화, 행동의 결과, 정적의 강도로 차이를 만든다.

반짝 웹툰은 첫 장부터 마지막 장까지 펼쳐 놓고 장별 고조와 완급을 검사한다. 현재 단편의 예는 `친절한 질문 → 기대에 들뜸 → 상상의 과열 → 멍해지는 정적 → 놀람과 능청`이다. 이 감정 순서를 모든 후속 작품의 고정 템플릿으로 만들지는 않는다. 각 장의 `dramatic_purpose/page_peak/visual_change_from_previous`가 실제 파일에서 보이는지 확인하고, 인접 컷의 표정·몸짓·구도가 반복되면 새 연출로 수정한다.

모든 완성 장을 원본과 모바일 폭으로 나란히 비교한다. 특히 연속 컷과 동일 장소로 돌아온 컷에서 몸·손·표정·배경 배치가 사실상 같은지 확인한다. `repetition_review`에 비교한 파일 해시·반복 의심 컷·실제 변화·판정을 남긴다. 말풍선을 가려도 상황이 진전되는 것을 알 수 있는지가 보조 판단 기준이다. 실제 픽셀 중복 탐지 도구를 쓰지 않았다면 자동 중복 검사 완료라고 주장하지 않는다.

의도적인 정지 개그·콜백·회상처럼 같은 그림이 웃음의 장치인 예외만 구체적 서사 효과와 사용자 선택 근거를 남긴다. 제작 속도·캐시 재사용을 예외 근거로 쓰지 않는다. 장면을 바꾼 뒤에도 [대사 순서](dialogue-reading-order.md), 대화축·화자·소품 연속성을 다시 검사한다.

## 다음 실행을 위한 기록

완성본의 실제 결과에 맞춰 `job.json`과 제작 패키지 manifest에 `creative_signature`를 남긴다. 계획만 기록하지 말고 실제 미리보기와 대조한 뒤 확정한다.

```json
{
  "concept_id": "editorial-photo-collage",
  "medium_family": "editorial-collage",
  "format_id": "interview-magazine",
  "layout_family": "editorial-spread",
  "hook_device": "기업의 질문에서 시작",
  "character_acting": "피오가 질문하고 테오가 사실을 해설",
  "card_count": 5
}
```

`concept-selection.json`에는 이전 6편 중 무엇과 어떻게 달라지는지, 선택 이유와 반복 예외를 남긴다. 별도 전역 상태 파일 없이 기존 공유 제작 이력의 완성 패키지를 읽는다. 이전 패키지의 구성 기록이 빠져 있으면 실제 미리보기를 검토한 `creative-signature.json` 보조 기록을 둘 수 있다. 이 기록은 해당 `manifest_sha256`·검토자·시각·실제 signature를 포함하며 기존 이미지·manifest·게시 이력을 바꾸지 않는다.

다양성은 입력과 기록만으로 보증되지 않는다. 최종 전체 미리보기를 최근 완성본과 나란히 보고 첫 장의 인상, 중간 장의 리듬, 캐릭터 행동, CTA가 실제로 달라졌는지 확인한다.
